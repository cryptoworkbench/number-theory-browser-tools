## Palette token specification (authoritative)

The literal palette is `index.html`'s existing palette, because the hub page already defines the site's visual identity and the shared header's night accent (`#7c9bff`) already matches it. One deliberate nudge: day `--accent-2` moves from `#0f6e68` to `#0f9a80` so the secondary accent and the "result" role are the same value in both themes instead of two near-identical teals.

Literal tokens (each one MUST be re-declared in the day block):

Derived tokens — declared **once** in `:root` and never re-declared in the day block, because `var()` resolves against the element's own computed custom properties and therefore follows the theme automatically:

| `--role-input` | `var(--accent)` | a user-supplied value, or the value currently being operated on |
| `--accent-soft` | `color-mix(in srgb, var(--accent) 16%, transparent)` | tinted accent background |
| `--role-result-soft` | `color-mix(in srgb, var(--role-result) 12%, transparent)` | tinted result background |
| `--role-input-soft` | `color-mix(in srgb, var(--role-input) 12%, transparent)` | tinted input background |
| `--role-warn-soft` | `color-mix(in srgb, var(--role-warn) 12%, transparent)` | tinted warning background |

| `--role-alt-soft` | `color-mix(in srgb, var(--role-alt) 12%, transparent)` | tinted second-participant background |

`color-mix(in srgb, …)` is already used in this codebase — `RSA Examplifier/rsa-examplifier.html` line 22 defines `--bob-bg` that way — so it is an established, browser-supported pattern here and needs no fallback.
