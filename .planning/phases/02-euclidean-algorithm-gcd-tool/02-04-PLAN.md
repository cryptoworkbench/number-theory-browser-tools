<objective>
Ship the Extended Euclidean half of the tool: an off-by-default toggle that adds `s` and `t` columns to the trace already on screen, and a closing identity line stating `gcd(A, B) = s·A + t·B = G` in full.

Purpose: this is the last requirement in the phase and the cheapest one to get wrong. The values are already there — plan 02-01's `euclidSteps` computes `s` and `t` in the same forward loop as `q` and `r` and attaches them to every step object and to the run, exactly as `02-RESEARCH.md` Pattern 3 prescribes, and plan 02-01's behavioural harness already asserts the per-row invariant `s·A + t·B === r` on every line. So no arithmetic is added here at all: the work is presentation, and the thing to protect is that it stays one derivation rather than becoming a second pass over the same data, which D-02 forbids in as many words.

Output: an `#extToggle` checkbox, a `.eq-s` / `.eq-t` column pair on every chain line, a column caption, and an `#identityLine` landing beat.

Wave rationale: wave 4, after 02-03. The same single-file constraint that serialized the earlier expansion plans applies here, and this plan edits `appendStepLine` and `renderAnswer` — two functions plan 02-03 also touches — so it must follow rather than run beside it.
</objective>

Ground truth, verified while planning against the forward recurrence plan 02-01 specifies. The per-line coefficients are the pair for which that line's remainder is a combination of the two original inputs: `step.s · A + step.t · B === step.r`.

For the default `240, 46` run the five lines carry, in order, `(s, t)` = `(1, -5)`, `(-4, 21)`, `(5, -26)`, `(-9, 47)`, `(23, -120)`. Check the second: `-4·240 + 21·46 = -960 + 966 = 6`, which is that line's remainder.

For `35, 18` the three lines carry `(1, -1)`, `(-1, 2)`, `(18, -35)`. Check the first: `35 - 18 = 17`, that line's remainder.

The run-level coefficients — the pair for the GCD itself, which the identity line in Task 2 uses — are:

| preset | A, B | gcd | run s | run t | check |
|---|---|---|---|---|---|
| 240, 46 | 240, 46 | 2 | −9 | 47 | −2160 + 2162 = 2 |
| 35, 18 | 35, 18 | 1 | −1 | 2 | −35 + 36 = 1 |
| 144, 12 | 144, 12 | 12 | 0 | 1 | 0 + 12 = 12 |
| 36, 36 | 36, 36 | 36 | 0 | 1 | 0 + 36 = 36 |
| 17, 0 | 17, 0 | 17 | 1 | 0 | 17 + 0 = 17 |
| 89, 55 | 89, 55 | 1 | −21 | 34 | −1869 + 1870 = 1 |
| 500000, 2 | 500000, 2 | 2 | 0 | 1 | 0 + 2 = 2 |

Two of these are worth stating as expectations rather than curiosities: the `gcd(a, 0)` run has no steps at all, so its identity comes entirely from the seed values and reads `1·17 + 0·0 = 17`; and the equal pair, the multiple pair and the huge-quotient pair all land on `(0, 1)`, because one input divides the other and the smaller one is already the GCD. A learner who expected a "clever" pair of coefficients there is learning something true.
