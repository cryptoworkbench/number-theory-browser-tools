Ground-truth vectors the finished page must reproduce. These were computed and checked while planning; treat them as the test oracle, not as illustrations.

Additive mode, N = 6 — `elements(6)` is `[0,1,2,3,4,5]`, `identity(6)` is `0`, `op(a,b,6)` is `(a+b)%6`:
- The rendered value grid, row `a` by column `b`, is exactly `(a+b) mod 6`. Row 3 reads `3 4 5 0 1 2`.
- Cell (row 3, col 5): `raw` is `8`, reduced value is `2` — the caption must read `3 + 5 = 8 ≡ 2 (mod 6)`, the exact form CAYLEY-03 names.
- Cell (row 2, col 4): `raw` is `6`, reduced value is `0` — caption `2 + 4 = 6 ≡ 0 (mod 6)`.
- Table shape: one `<thead>` row of 7 `<th>` (corner + 6 column headers) and 6 `<tbody>` rows of 1 `<th>` + 6 `<td>`.

Multiplicative mode — `elements` is `unitsMod`, `identity(N)` is `1 % N`, `op(a,b,N)` is `(a*b)%N`:
- `unitsMod(6)` is `[1,5]`; the 2×2 value grid is `1 5 / 5 1`; `identity(6)` is `1`.
- `unitsMod(8)` is `[1,3,5,7]`; `identity(8)` is `1`; cell (3,5) has `raw` `15` and value `7` — caption `3 × 5 = 15 ≡ 7 (mod 8)`.
- `unitsMod(5)` is `[1,2,3,4]`; cell (2,3) has `raw` `6` and value `1`.
- `unitsMod(120)` has 32 elements (φ(120) = 32) — the multiplicative table is far smaller than the additive one at the same N, which is why every size-derived number in this tool keys off `M = elements(N).length`, never off N.

Degenerate moduli that must not throw:
- N = 1 additive: `elements` `[0]`, `identity` `0`, single cell value `0`.
- N = 1 multiplicative: `gcd(0,1)` is `1`, so `unitsMod(1)` is `[0]` and `identity(1)` is `1 % 1 = 0` — a 1×1 table whose only cell value is `0`. The trivial group; it is consistent, not a bug, and must render rather than produce an empty table.
- N = 2 multiplicative: `unitsMod(2)` is `[1]`, `identity` is `1`, single cell value `1`.

Input validation vectors: `0` and `-4` clamp up to `1`; `500` clamps down to `MAX_N` (120); `abc` and an empty field are rejected with the previous table left standing; every clamp or rejection writes a sentence into the note element.

Default load state: N = 6, additive, with the cell at row index 3 / column index 5 pre-selected, so the page opens on the worked example `3 + 5 = 8 ≡ 2 (mod 6)` — this repo's established "run an example on page load" convention.

**Table structure and CSS — the architectural core.** Render a real semantic `<table>` (05-RESEARCH.md Pattern 2), not SVG and not a `<div>` grid: `<caption>` describing the table, one `<thead>` row whose first cell is `th.corner` showing `mode.sign` (the `+` or `×` — 05-RESEARCH.md Open Question 2) and whose remaining cells are `th.ch[scope="col"][data-ci]`, then one `<tbody>` row per element with a leading `th.rh[scope="row"][data-ri]` followed by `td.cell[data-ri][data-ci][data-row][data-col][data-val]`. `data-row`/`data-col` carry the element *values*; `data-ri`/`data-ci` carry their positions in the element list — the two differ in multiplicative mode and later plans depend on both.

Required CSS properties, each with a reason the executor must not "simplify" away:

- `.cayley-table{ border-collapse:separate; border-spacing:0; table-layout:fixed; font-family:'JetBrains Mono', monospace; }` — `separate` rather than `collapse` because collapsed borders are owned by the table, not the cell, and therefore do not travel with a `position:sticky` header; `fixed` so every column takes its declared width instead of being sized by content.
- Every `th` and `td` gets `width`, `min-width` and `height` all set to `var(--cell-min)` so cells stay square (the square cell is what makes plan 05-02's diagonal hairline read as one continuous line), plus `text-align:center`, a right and bottom `1px solid var(--panel-border)` separator, and `font-size: clamp(9px, calc(var(--cell-min) * 0.40), 15px)` so the digits shrink with the cell.
- Declare `--cell-min: 46px` once on `.table-scroll` as a fallback. Plan 05-03 replaces that single static value with a `cellMinPx(M)` breakpoint function written over it via `setProperty`; leave the declaration as the only place the number appears so that swap is a one-line change.
- `.table-scroll{ overflow:auto; max-height:70vh; border-radius:14px; border:1px solid var(--panel-border); background:var(--panel); }` — the scrolling container is D-02's mechanism and must exist from the start, even though this plan only renders small tables.
- `thead th{ position:sticky; top:0; z-index:2; background:var(--bg-2); }`, `tbody th{ position:sticky; left:0; z-index:1; background:var(--bg-2); }`, `th.corner{ position:sticky; top:0; left:0; z-index:3; background:var(--bg-2); }`. Sticky cells need an opaque background or the scrolled body shows through them; the corner must outrank both axes.

**Script — a single `(function(){ "use strict"; ... })();` IIFE**, sectioned with the repo's `/* ---------- name ---------- */` markers in this order: math helpers, `MODES` config, state, DOM references, input reading, table build, highlight pass, caption, persistence, event wiring, load-time example.

Math helpers, duplicated verbatim from `Congruence Wheel/congruence-wheel.html:521-524` per D-01 and 05-RESEARCH.md's "Don't Hand-Roll" row — do not re-derive them: `clamp(v, lo, hi)`, `gcd(a, b)` as the iterative remainder loop, and `unitsMod(N)` as the `gcd(r, N) === 1` filter over `0..N-1`. Declare `unitsMod` as a hoisted `function` declaration, not a `var` assignment, because `MODES.multiplicative.elements` references it directly by name at object-literal evaluation time.

`MODES` — duplicate the config *shape* from `Congruence Wheel/congruence-wheel.html:435-472` (D-01 names this explicitly), keyed `additive` and `multiplicative`, each supplying: `elements(N)` (`0..N-1` for additive, `unitsMod` for multiplicative), `op(a,b,N)`, `raw(a,b)` (the unreduced sum or product, needed for the `8 ≡ 2` half of the caption), `identity(N)` (`0` and `1 % N`), `sign` (`+` and `×`), `words` naming the two operands and the result per mode (row operand / column operand / sum, versus / product), and `summary(N, els)` returning the `#group-summary` line. Keep the function signatures identical to the wheel's; adapt only the strings for a table context. Plans 05-02 and 05-03 add further wording fields to these same two objects, so keep them formatted for extension.

`state = { N: 6, mode: 'additive', ri: null, ci: null }`. Restore `{N, mode}` from `localStorage` under the key `cayley-table` inside a `try/catch`, validating every field before assigning — `N` only when it parses as an integer within `1..MAX_N`, `mode` only when it is exactly `'additive'` or `'multiplicative'` — copying the guard shape at `Congruence Wheel/congruence-wheel.html:486-491`. A malformed or tampered stored value must leave the defaults standing, never reach `buildTable`. Declare `MAX_N = 120` as a named constant.

`MAX_N = 120` is the practical ceiling D-02's discretion note asks for, and the number is derived, not copied: additive mode is the worst case at `N` elements (multiplicative is only φ(N)), so 120 means at most 120×120 = 14,400 `<td>` plus 241 `<th>` = 14,641 nodes, under the 20,000-node ceiling the Sieve already ships and proves (`Sieve Of Eratosthenes/sieve-of-eratosthenes.html:753` clamps its size to 20000), while being exactly double the Congruence Wheel's `max="60"` so it reads as generous next to the sibling tool rather than as the tight cap D-02 rejected. Plan 05-03 measures render time at this ceiling and lowers it only if the measurement says so.

`readN()` returns an integer or `null`. Write one specific sentence into `#n-note` with `textContent` — never `innerHTML`, since this is the one place a raw typed string reaches the page — for each outcome: a field that is empty or does not parse as a whole number is rejected and the current table is left standing; a value below 1 is raised to 1 and the change is announced; a value above `MAX_N` is lowered to `MAX_N` and the cap is announced by name (a cap is never silent — Phase 02's established rule); a value inside the range clears the note. When a clamp happens, write the clamped number back into `#n-input.value` so the field and the table never disagree.

`buildTable()` is the expensive path and runs only when N or mode changes: read `mode.elements(state.N)` into `els`, set `M = els.length`, empty the table, then build `<thead>` and `<tbody>` into a single `DocumentFragment` before one append — at the ceiling this is fourteen thousand nodes and appending per-cell would thrash layout. Keep module-scoped `cellMatrix` (an `M`-long array of `M`-long `<td>` arrays), `rowHeads` and `colHeads` arrays populated during the build, so the highlight pass can reach any row or column in O(M) without querying the DOM. Fill `#group-summary` from `mode.summary(N, els)`. Then clamp the selection into range and call `applyHighlights()`.

Do **not** attach a listener per cell. Attach one delegated `click` listener to `#cayley-table` that resolves the clicked node with `closest('td.cell')`, reads `data-ri`/`data-ci`, and calls `select(ri, ci)`. Fourteen thousand listeners is the difference between a page that opens and one that does not.

`applyHighlights()` is the cheap path and runs on every selection change. It must clear only what it previously set — keep `prev = {ri, ci}` and un-set exactly those nodes — and then set: `is-a` on `rowHeads[ri]`, `is-b` on `colHeads[ci]`, `is-a-row` on every `<td>` of row `ri`, `is-b-col` on every `<td>` of column `ci`, and `is-sum` on `cellMatrix[ri][ci]`. That is O(M) work per click, never O(M²): 05-RESEARCH.md Pitfall 3 records that the Congruence Wheel's `select(){ …; render(); }` full-rebuild shape is fine for sixty wedges and wrong for fourteen thousand cells, and this is the adaptation. CSS-wise `.is-sum` must be declared after `.is-a-row` and `.is-b-col` so the solid result fill wins over the two operand washes on the intersection cell.

`updateCaption()` writes the equation into `#cayley-caption`, adapting the wheel's caption builder (`Congruence Wheel/congruence-wheel.html:710-717`): a leading bracketed slot line with `span.slot-a`, `span.slot-b` and `span.slot-sum` carrying the two operands and the result, then the spelled-out arithmetic `a sign b = raw ≡ value (mod N)`. Every interpolated value is a computed integer, so string building is safe here; the raw `<input>` string is never interpolated into markup. Give `.caption .slot-a`, `.slot-b`, `.slot-sum` the matching `--slot-*` colors and `font-weight:600`, exactly as the wheel does at its lines 197-199, so the caption's colors name the same things the table's colors name.

`select(ri, ci)` sets the selection, calls `applyHighlights()` and `updateCaption()`, and moves the roving `tabindex`: the selected `<td>` gets `tabindex="0"` and the previously selected one `tabindex="-1"`. Support keyboard selection from the focused cell with a `keydown` handler on the table — `ArrowUp`/`ArrowDown` move `ri`, `ArrowLeft`/`ArrowRight` move `ci`, each clamped to `0..M-1`, `preventDefault` so the container does not scroll instead, and the newly selected cell takes focus. This is the same roving-focus device the mode tabs already use (`Congruence Wheel/congruence-wheel.html:1031-1039`), so it introduces no new convention, and it is what keeps a click-only table reachable without a pointer.

`defaultSelection(els)` picks the load-time example deterministically: `ri = Math.min(3, M-1)`, `ci = Math.min(5, M-1)`, and if that lands on the diagonal while `M > 1`, move `ci` to `(ri + 1) % M`. At the default N = 6 additive this is exactly row 3 / column 5, so the page opens on `3 + 5 = 8 ≡ 2 (mod 6)` — the very equation CAYLEY-03 names — and always opens off-diagonal when the group has more than one element, which is what plan 05-02's mirror echo needs in order to be visible on arrival.

`setMode(id)` and `syncTabs()` duplicate `Congruence Wheel/congruence-wheel.html:1005-1041` including the click and `ArrowRight`/`ArrowLeft` wiring: toggle `is-active`, set `aria-selected`, move `tabIndex`, point the panel's `aria-labelledby` at the active tab, then reset the selection to `defaultSelection`, `persist()` and `buildTable()`.

`persist()` writes `{N, mode}` to `localStorage` under `cayley-table` inside a `try/catch` — the same key-per-tool convention as the wheel's `congruence-wheel`, and the `try/catch` matters because writes are silently unavailable on some `file://` origins (Phase 01 plan 01-06 hit exactly this). The selection is deliberately not persisted; the load-time example should be the same worked equation every time.

Event wiring at the bottom: `#n-input` `input` and `change` call a `regenerate()` that runs `readN()`, stores the result, resets the selection to `defaultSelection`, persists and rebuilds; the two mode tabs wire to `setMode`; the table carries the delegated `click` and the `keydown`. Finish with `window.addEventListener('load', ...)` calling `syncTabs()` then `buildTable()` so the page opens on a complete worked table.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| keyboard → `#n-input` → page DOM | The only untrusted input this tool has: one `<input type="number">` whose raw string value reaches the page's own JavaScript and drives an O(M²) DOM build. |
| `localStorage` → page state | The `cayley-table` key this plan introduces is read back into `state` on load, and the shared `site-theme` key is read by the pre-paint theme script. Anything already in a visitor's own storage is attacker-controllable in the threat sense. |

There is no network call, no server, no authentication, no session and no account introduced by this plan. The page is 100% client-side static HTML, CSS and JavaScript loaded over `file://` or plain static hosting. The phase's API-coverage, schema-push and assumption-delta checkpoints are inapplicable for the same reason they were in Phases 01 and 02: there is no external API or SDK, no schema, and no identity model.
