<objective>
Turn the working table from plan 05-01 into the teaching artifact the phase is actually for: make the identity's row and column visible, ring the elements that are their own inverse, draw the diagonal as an axis of symmetry, and echo every selected cell's twin across that diagonal with both equations spelled out.

Purpose: these three states (D-04, D-05, D-06) are the phase's pedagogical payload, and CONTEXT.md flags their coexistence as the hard part — up to four states can land on one cell at once, and four competing background hues would collapse into noise (05-RESEARCH.md Pitfall 4). This plan therefore assigns each state its own *visual channel* rather than its own hue, and verifies the coexistence rather than assuming it.

Output: the same single file, extended with one static-state pass, one mirror echo, a per-mode symmetry note, a derived-notes line, and a four-state legend.
</objective>

The identity's position in the element list is index `0` in both modes, always: additive `elements(N)` starts at `0` which *is* the additive identity, and for every `N ≥ 2` the smallest unit is `1`, which is the multiplicative identity, while for `N = 1` the only unit is `0` and `identity(1)` is `1 % 1 = 0`. The code must still locate it with `els.indexOf(mode.identity(N))` and guard against `-1` rather than hard-coding `0` — the assertion is that the lookup lands on `0`, not that the lookup is skipped.

Self-inverse elements, `op(x, x, N) === identity(N)`:
- N = 6 additive → `0` and `3` (since `3 + 3 = 6 ≡ 0`). Exactly 2 ringed cells, at diagonal positions 0 and 3.
- N = 8 additive → `0` and `4`. Exactly 2.
- N = 7 additive → `0` only (7 is odd, so no element doubles to 0 other than 0). Exactly 1.
- N = 6 multiplicative → elements `[1,5]`, identity `1`; `1·1 = 1` and `5·5 = 25 ≡ 1`. Both, so 2 of 2.
- N = 8 multiplicative → elements `[1,3,5,7]`, identity `1`; `9 ≡ 1`, `25 ≡ 1`, `49 ≡ 1`. All 4 — every element is its own inverse.
- N = 12 multiplicative → elements `[1,5,7,11]`; `25 ≡ 1`, `49 ≡ 1`, `121 ≡ 1`. All 4.
- N = 5 multiplicative → elements `[1,2,3,4]`; `4 ≡ 4` no, `9 ≡ 4` no, `16 ≡ 1` yes. Exactly 2: `1` and `4`.
- N = 7 multiplicative → elements `[1..6]`; only `1` and `6` (`36 ≡ 1`). Exactly 2.
- N = 1, either mode → the single cell is both the identity cell and self-inverse. Exactly 1.

Coexistence case to verify rather than assume: at N = 6 additive the cell at row 0 / column 0 is simultaneously in the identity row, in the identity column, and self-inverse — and becomes the click selection too if clicked. Ground-truth vectors for the mirror relation, computed while planning:

- N = 6 additive, select row 2 / column 4: value `0`. Mirror is row 4 / column 2, also value `0`. Notes must state both `2 + 4 = 6 ≡ 0 (mod 6)` and `4 + 2 = 6 ≡ 0 (mod 6)`.
- N = 6 additive, select row 3 / column 5: value `2`; mirror row 5 / column 3, value `2`.
- N = 8 multiplicative, select the cell for values 3 and 5: value `7`; mirror is the cell for 5 and 3, also `7`, with `3 × 5 = 15 ≡ 7 (mod 8)` and `5 × 3 = 15 ≡ 7 (mod 8)`.
- Diagonal selection, N = 6 additive row 3 / column 3: there is no second cell — the twin is the cell itself. Exactly zero mirror-marked cells, and the notes say so instead of drawing a second outline on the same cell (05-RESEARCH.md flags this special case explicitly).
- The invariant that makes the teaching point true, and that the harness checks over the whole table rather than one pair: for every `ri`, `ci`, the value at `(ri, ci)` equals the value at `(ci, ri)`. It holds in both modes for every N because both operations are commutative — which is exactly the fact the diagonal symmetry is showing.
- Diagonal cell count equals `M` in every mode and modulus.
  </behavior>
  <action>
Extend the same file with D-05's treatment. CAYLEY-05 and the roadmap's fourth success criterion both demand that mirrored pairs be "readable as such in the diagram rather than merely asserted in prose", so this is three cooperating pieces — a static axis, an interactive echo, and words that name what the learner is looking at — per 05-RESEARCH.md Open Question 1's recommendation to do both rather than pick.

**One new alias**: `--slot-diag: var(--role-inert)`. The diagonal axis is structure, not a value, and `--role-inert` is this palette's structural/inert role — it reads as a quiet guide line in both themes rather than competing with the four meaning-carrying states.

**The static axis.** Mark every `<td>` where `ri === ci` with `on-diag`, assigned inside the same build pass as Task 1's static classes. Style it as a pseudo-element hairline, not a border and not a background: give the cell `position:relative` and `.on-diag::after` `content:""`, `position:absolute`, `inset:0`, `pointer-events:none`, and a corner-to-corner 45-degree `linear-gradient(to bottom right, ...)` that is transparent either side of a roughly 1px band of `var(--slot-diag)` through the middle. Because plan 05-01 made every cell square (`width` and `height` both `var(--cell-min)`), the per-cell hairlines line up into one continuous diagonal across the whole table. A pseudo-element is a fifth, otherwise-unused layer — it cannot collide with the background wash, the ring, the fill or the outline, which is precisely why the axis is drawn this way rather than as a border.

**The interactive echo.** In `applyHighlights`, when `ri !== ci`, add `is-mirror` to `cellMatrix[ci][ri]`; when `ri === ci`, add it to nothing. Clear it the same way the other selection classes are cleared — from the previously mirrored cell only, keeping the pass O(M). Style `.is-mirror` as `outline: 2px dashed var(--slot-sum); outline-offset: -3px` — an outline, the fourth channel, reusing the selected cell's own hue so the learner reads "this is the same answer over there" rather than "this is a fifth kind of thing", and dashed rather than solid so it is distinguishable from the self-inverse ring underneath it. This echoes the Congruence Wheel's own device for a cell carrying a second role (`Congruence Wheel/congruence-wheel.html:160` changes `stroke-dasharray`, not fill, for exactly this reason).

**The words.** Add a `#cell-notes` paragraph under the existing `#cayley-caption`, styled like the caption but dimmer, and a new `updateNotes()` called wherever `updateCaption()` is called. It writes, from the current selection: the mirror sentence — the twin's equation in full (`4 + 2 = 6 ≡ 0 (mod 6)`) followed by the point, that the twin lands on the same value so the table is symmetric about its diagonal and the group is commutative; or, when the selection is on the diagonal, that this cell sits on the axis and is its own twin. When the selected cell also carries the self-inverse ring, append a sentence using Task 1's `inverseWord` naming the element as `its own negative` / `its own reciprocal` because the cell's value is the identity. Every interpolated value is a computed integer, as in `updateCaption`.

Add a `symmetryNote` field to each of the two `MODES` objects and render it into a static `#symmetry-note` line placed near the table, refreshed on every build: additive phrased around `a + b` and `b + a` landing on the same class, multiplicative around `a · b` and `b · a`, each ending with the invitation to click a cell and watch its twin light up. This is the prose that supports the diagram, not the substitute for it.

**The legend.** Add a `#legend` block under the table with four `.legend-item` entries — identity row and column, own inverse, selected cell with its operands, mirror twin — each carrying a small `.legend-swatch` element styled with *the same channel that state uses in the table*: a wash plus edge bar, an inset ring, a solid fill, a dashed outline. A legend drawn in different channels from the table teaches the wrong mapping, so the swatches must reuse the same declarations. Keep the whole legend to one wrapped row of short labels.

Do not change the value computation, the element lists, the input validation, or Task 1's static classes.
