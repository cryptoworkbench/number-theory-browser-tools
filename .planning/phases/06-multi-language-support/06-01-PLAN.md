## Planning assumptions (no CONTEXT.md — user chose "continue without context"; each is a recorded default, reviewable at the end-of-phase UAT)

- A1 (language identity — the assumption-delta question, answered): the language is ONE site-wide preference, not per-page or per-tool state. It is resolved URL `?lang=` → cookie → localStorage → browser default, mirroring `site-theme`, implemented independently inside assets/nt-i18n.js (never calling theme.js, never routed through NT.store, whose documented scope is sibling-pair settings). The exact persisted key/format is gated by Task 2 (recommended: `site-lang`, raw two-letter code).
- A2 (fallback): English is the source-of-truth dictionary. Every shipped language must carry exactly the English key set — a missing key is a check failure (i18n-check `--coverage`, 06-02), not a silent runtime fallback. `translate` still falls back to English, then to the key itself, purely defensively.
- A3: a first visit defaults to the first `navigator.languages` entry whose two-letter prefix is supported, else English. The detected default is not persisted; only an explicit choice (switcher, `?lang=` link, or an already-stored value) is written.
- A4: the switcher is a native `<select id="lang-switch-select">` placed after `</nav>` and before the theme toggle, options in the order the user listed the languages (Nederlands, English, Deutsch, Français, Español), each labelled by its autonym with a matching `lang` attribute, English carrying `selected` in markup because English is the static-markup default.
- A5 (dictionary location): the engine lives in assets/nt-i18n.js; ALL translation data lives under assets/i18n/ — `site.js` for the shared chrome (`site`) and, from 06-02, the shared control vocabulary (`common`), plus one `assets/i18n/<page-slug>.js` per page registering only that page's namespace. Justification: one shared dictionary file would make every per-tool plan edit the same file (forcing 14 serial waves) and make every page download every page's strings; strings inline in each page would bloat pages two- to three-fold (RSA ~+2000 lines) and mix five languages of prose into tool logic. Per-page data files keep wave-3 plans file-disjoint, keep pages lean, and give translators one directory.
- A6: tool names keep eponyms/proper nouns (RSA, Diffie-Hellman, Euler, Fermat, Cayley, Venn, Shor, Euclid, Eratosthenes — with the conventional per-language spelling of the eponym) and translate the common-noun part.
- A7: numerals are never localized. The existing comma-grouped `NT.bigint.fmt` output and plain `toString()` output stay byte-identical in all five languages; no locale number formatting anywhere (I18N-06).
- A8: a brief flash of English static text before the end-of-body module applies a non-English language (06-RESEARCH Pitfall 4) is accepted; no hide-until-ready mechanism.
- A9: tone — Dutch informal (je), German informal (du), French vous, Spanish tú; formalized in 06-02's glossary.
- A10: the spec-less probe fallback was skipped (phase had no requirement IDs to probe at planning start) — recorded, not silently dropped.

## NT.i18n contract (normative — every later Phase 6 plan builds on exactly this)

Files and load order. `assets/nt-i18n.js` is a classic script: IIFE, "use strict", builds one frozen object, assigns it to `window.NT.i18n` (creating `window.NT` if absent) and locks the slot with `Object.defineProperty(NT, 'i18n', { writable: false, configurable: false })`; `window.NT` stays extensible. Evaluating it must never throw even when `document`, `navigator`, `location`, `localStorage`, `history` or `window.addEventListener` are missing (guard each with typeof checks or try/catch), because Phase 7's Node harness loads it in a bare vm context from 06-02 on. Data files `assets/i18n/site.js` and `assets/i18n/<page-slug>.js` are classic scripts (IIFE, "use strict") whose only statement is `NT.i18n.register(...)`. Tool pages include, at the end of `<body>`, in this order and all plain (no defer/async/module): their existing nt-*.js modules in canonical order (core, bigint, svg, store, layout — whichever they already use), then `../assets/nt-i18n.js`, then `../assets/i18n/site.js`, then `../assets/i18n/<page-slug>.js`, then the page's own inline `<script>`. index.html (06-03) uses the same three with root-relative `assets/` paths, immediately before `</body>`.

Exports (final set after Task 3): `SUPPORTED_LANGS` (frozen array `['nl','en','de','fr','es']`), `LANG_STORAGE_KEY` (Task 3), `applyStaticDom(root)`, `bindText(el, key, params)`, `detectDefaultLang()`, `getLang()`, `onLangChange(fn)`, `register(ns, dict)`, `setLang(lang)`, `translate(key, params)`, `translateInto(el, key, params)`. These names were chosen because the single-letter `t` collides with existing local `t` bindings in all 16 pages (Bézout coefficient, animation progress, loop counters) and `tr` with table-row locals in two pages; none of the chosen names is bound anywhere in the repo today.

- Keys are `'<ns>.<rest>'`: ns is the text before the first dot, rest is a flat key that may contain further dots. Namespaces: `site`, `common` (06-02) and one per page: hub (index.html), sieve, factorTree, venn, euclid, crt, wheel, totient, cayley, iso, sqm, dh, ecdh, rsa, fermat, shor — the data file for page `X/x-y.html` is `assets/i18n/x-y.js` (index.html → `assets/i18n/hub.js`).
- `register(ns, dict)`: ns must match /^[a-z][A-Za-z]*$/; dict must have an own `en` object; each language object is frozen on registration; registering an already-registered namespace throws an Error naming it. Entry values are strings or plural objects `{ one, other }`.
- `translate(key, params)` returns a string. Lookup uses own-property checks only (so `__proto__`, `constructor`, `toString` keys resolve to nothing): current language, then `en`, else the key itself unchanged. For a plural entry the count is `Number(params.count)` (when `params.count` is a DOM Node, `Number(params.count.textContent)`); category is `new Intl.PluralRules(lang).select(count)` — `one` selects `entry.one`, every other category selects `entry.other`; without `Intl.PluralRules`, count 1 is `one`. Substitution is one pass of `/\{([A-Za-z0-9_]+)\}/g`: a name that is an own property of params becomes `String(value)` (a Node becomes its textContent); an unknown name stays as written; substituted text is never re-scanned. Numbers are never formatted — `String()` only.
- `translateInto(el, key, params)` resolves the template exactly like `translate` (including plural selection) but renders it as nodes: it empties `el` with `el.textContent = ''`, then appends a text node per literal segment and, per placeholder, the param itself when it is a DOM Node (has a nodeType) or a text node of `String(value)`; an unknown placeholder renders as its literal text. It removes `data-i18n` and `data-i18n-params` from `el` (the element is JS-owned from then on) and returns `el`. Never touches innerHTML.
- `bindText(el, key, params)`: with a null/undefined key it sets textContent to '' and removes `data-i18n`/`data-i18n-params`; otherwise it sets `data-i18n` to the key, `data-i18n-params` to `JSON.stringify` of params with every value passed through `String` (attribute removed when params is absent), and textContent to `translate(key, params)`. Bound elements re-render automatically on every language change. Params must be strings, numbers or BigInts.
- `applyStaticDom(root)` (root defaults to document): for every element carrying `data-i18n` — parse `data-i18n-params` inside try (null on error); if the element has element children, the first visit records its child elements in document order in an internal WeakMap and every visit renders the template as nodes with params `{0: child0, 1: child1, ...}` merged with the attribute params, re-inserting those same child nodes (rich static markup: `<p data-i18n="k">You supply <strong>two</strong> primes</p>` with English value `You supply {0} primes`); otherwise it sets textContent to `translate(key, params)`. The element keeps its `data-i18n` attribute. Then for each of title, aria-label and placeholder, every element carrying `data-i18n-title` / `data-i18n-aria-label` / `data-i18n-placeholder` gets that attribute set to `translate(value)`. Never innerHTML.
- `getLang()` returns the active code. `setLang(lang)`: a value not exactly in SUPPORTED_LANGS returns false with no side effect; the already-active language returns true with no side effect; otherwise it sets the active language, (Task 3: persists it), sets `document.documentElement.lang`, runs `applyStaticDom(document)`, re-decorates links, sets `#lang-switch-select`'s value, dispatches `new CustomEvent('nt-i18n:change', { detail: { lang } })` on window exactly once, and returns true.
- `onLangChange(fn)` adds a window listener for `nt-i18n:change` that calls `fn(lang)`.
- `detectDefaultLang()` returns the first entry of `navigator.languages` (or `[navigator.language]`) whose first two characters, lowercased, are supported; else `'en'`.
- Resolution at evaluation time: `?lang=` (exact allow-list match after decodeURIComponent inside try, read with `new RegExp('[?&]lang=([^&#]*)')` on location.search) → (Task 3: cookie → localStorage) → `detectDefaultLang()`. `document.documentElement.lang` is set during evaluation.
- Init runs on DOMContentLoaded (immediately when `document.readyState !== 'loading'`): `applyStaticDom(document)`, decorate links, set the select's value and wire its `change` event to `setLang(select.value)`; Task 3 adds persistence of an explicit choice, stripping `lang` from the address bar, and the cross-tab storage listener.
- Link decoration copies theme.js's `decorateLinks` algorithm with its own `LANG_PARAM = 'lang'` and `PARAM_RE = new RegExp('([?&])' + LANG_PARAM + '=[^&]*&?')`: skip empty hrefs, `#`-only hrefs and scheme-qualified hrefs; strip only `lang=`; drop a trailing `?`/`&`; append `?lang=xx` or `&lang=xx`; keep the `#hash`. It never touches `theme=` or a tool's own parameters (`a`, `b`, `n`, `m`, `mode`, `ext`), and re-decorating replaces rather than appends.

DOM attribute contract: `data-i18n`, `data-i18n-params`, `data-i18n-title`, `data-i18n-aria-label`, `data-i18n-placeholder`. An element whose text the page script writes at runtime is JS-owned and carries no `data-i18n` unless the script writes it exclusively through `bindText`.

Dictionary rules: flat keys; the same key set in nl/en/de/fr/es; the same placeholder names per key in every language; plural entries are `{one, other}` in all five; values are plain text (no markup); English values reproduce today's English output byte-for-byte; numerals and math notation are written exactly as in English; emoji/glyph prefixes of labels (▶, ⏭, 🧮, →) are part of the value, never concatenated in code.

Canonical header (identical on every page apart from relative hrefs and which link has `is-active`): brand label `<span class="site-brand-label" data-i18n="site.brand">`; `<nav class="site-nav" aria-label="Tools" data-i18n-aria-label="site.nav.label">`; each nav link gains `data-i18n="site.nav.<id>"` with ids home, sieve, factorTree, venn, euclid, crt, wheel, totient, cayley, iso, sqm, dh, ecdh, rsa, fermat, shor (in the existing nav order); then, after `</nav>`, a `<label class="lang-switch" title="Language" data-i18n-title="site.lang.label">` containing `<span class="lang-switch-icon" aria-hidden="true">🌐</span>` and `<select id="lang-switch-select" aria-label="Language" data-i18n-aria-label="site.lang.label">` with options `nl` Nederlands, `en` English (selected), `de` Deutsch, `fr` Français, `es` Español, each option carrying `lang="<code>"`; then the existing theme label with `data-i18n-title="site.theme.toggle"` and its `#theme-switch-input` with `data-i18n-aria-label="site.theme.toggle"`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| location.search → nt-i18n.js | the `?lang=` value is attacker-controllable text arriving with any link |
| document.cookie / localStorage → nt-i18n.js | stored values may be stale, hand-edited or written by another page |
| dictionary values + params → DOM | strings rendered into every page; params may carry user or URL input |
| nt-i18n.js → every same-site `<a href>` | link rewriting runs over links the module does not own |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-01 | Tampering | fromUrl / setLang / storage listener | high | mitigate | Every incoming code passes valid() — exact match against the frozen five-code allow-list — before it is used as a lookup key, written to storage/cookie, put in a URL or set as html lang; anything else is ignored (asserted by --api and --persistence with 'xx', 'DE', '<script>', '__proto__', '') |
| T-06-02 | Tampering | translate / translateInto / bindText / applyStaticDom | high | mitigate | Translated text and params are only ever inserted as text nodes or via textContent/setAttribute; the module contains no innerHTML; the --api fake DOM throws on any innerHTML assignment |
