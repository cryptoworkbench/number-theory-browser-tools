## Per-page translation procedure (normative — 06-03 … 06-11 apply it to their pages; this plan applies it to the Sieve first)

P1 Header — the page's `<header class="site-header">` block becomes the canonical header (06-01 contract): same markup as the Sieve's, every href still resolving to the same target from this page's directory, `is-active` only on the page's own link (its bare filename). Gate: `i18n-check.js --header "<page>"`.
P2 Includes — after the page's existing nt-*.js includes (canonical order), add `../assets/nt-i18n.js`, `../assets/i18n/site.js`, `../assets/i18n/<slug>.js`, immediately before the inline script, all plain. Gate: `--includes`.
P3 Import — `const { … } = NT.i18n;` as the last line of the import block (after any NT.layout line), names sorted by code point, exactly the names used. Gate: shadow-check.
P4 Dictionary — `assets/i18n/<slug>.js` registers the page namespace in nl/en/de/fr/es per the contract's dictionary rules. English values copy today's English output byte-for-byte. Translations follow 06-GLOSSARY.md (tool names, terms, tone, punctuation). Strings already in `common` are referenced as `common.*`, never duplicated; a per-tool plan never edits assets/i18n/site.js — a shared-looking string not yet in `common` goes into the page namespace.
P5 Static markup — every user-visible text in the page's markup (incl. `<title>`, labels, buttons, chips, legends, captions, footers, `<option>`s) gets `data-i18n`; elements mixing text and child elements use the rich form (child elements become {0}, {1}, … in the value); title/aria-label/placeholder attributes get data-i18n-title / data-i18n-aria-label / data-i18n-placeholder. JS-owned elements get no data-i18n. Text that is pure math notation, numbers or proper nouns needs no key. Gate: `--literals-markup`.
P6 Dynamic strings — every user-visible string the script produces (textContent, SVG `<text>`/`<title>`, aria-label/title attributes, error and status messages, step logs, captions, preset/chip labels built in JS, export status text) goes through translate / translateInto / bindText with ONE whole-sentence template per message and params for every computed value — never concatenation of translated fragments, never a translated fragment glued to a literal. Markup-building innerHTML/template strings that contain prose become DOM construction (createElement / svgEl + textContent) with translateInto and Node params, producing the identical English DOM. Display-word tables (e.g. SPEED_LABELS) are replaced by keys (`'common.speed.' + value` is the one allowed key-prefix concatenation) and the local table is deleted. User- or URL-supplied text is only ever passed as a param (it becomes a text node). Gate: `--literals-js` and `--coverage`.
P7 Re-render — one `onLangChange(function () { … })` registration in the event-wiring section re-renders every JS-owned text from current state (bindText slots re-render automatically). Playback tools keep their state: re-render the current step's texts, or rebuild the log/run and replay silently to the current step index, restoring play/pause exactly. No reload, no reset. Avoid adding named helper functions whose name and body would be identical across pages; put generic glue in the anonymous callback. Gate: i18n-browser `switch`.
P8 Numbers — numerals are never locale-formatted. Any existing browser-locale number formatting call is replaced by `NT.bigint.fmt` (include nt-bigint.js in canonical order and import fmt), which yields today's en-US output. Gate: `--no-locale-number-format`, and en-parity.
P9 Config — `.planning/phases/06-multi-language-support/i18n-config/<slug>.json` only when an exemption is genuinely needed; every entry carries a reason. Keys: `allowSame` {"<ns>.<key>": reason} (value legitimately identical to English in some language), `allowLiteral` {"<exact text>": reason}, `allowRenderText` {"<exact text>": reason}, `volatile` [regex] (language-independent patterns for time-dependent text), `enParityExceptions` [{pattern, replace, reason}] (intentional English output changes — avoid; prefer identical), `switchPoints` [top-level snap labels], `runs` (only to add steps that reach strings Phase 7's step list never shows).
P10 Gates — per page: `node .planning/phases/06-multi-language-support/i18n-check.js "<page>"` (all static modes), `node .planning/phases/07-shared-js-module-refactor/shadow-check.js "<page>"`, `node .planning/phases/06-multi-language-support/i18n-browser.js "<page>"` (all runtime modes). All three must pass before the page's last commit.
