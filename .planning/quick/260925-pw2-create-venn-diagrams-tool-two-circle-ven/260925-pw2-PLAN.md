<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user input -> DOM | Prime values chosen in the picker and dragged/dropped are written back into the page as SVG text and readout strings |
| localStorage -> app state | Restored placement state is attacker-controllable on a shared machine or via devtools, and is read on every page load |
| drag payload -> app state | `dataTransfer` content on a drop can originate from outside the page (another tab, the desktop) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-pw2-01 | Tampering | token/readout rendering in `renderTokens` and `renderProducts` | medium | mitigate | Every dynamic value is written with `textContent`; the only permitted `innerHTML` use is clearing a container with an empty string, enforced by the `RICH-INNERHTML` gate in Tasks 1 and 2 |
| T-pw2-02 | Tampering | `restore()` reading `localStorage['venn-diagrams']` | medium | mitigate | Parse inside try/catch, then validate shape: object with three array keys, each at most `MAX_PER_REGION` entries, every entry passing `isPrime`; any failure discards the stored value and falls back to the seeded example |
| T-pw2-03 | Tampering | `drop` handler reading `ev.dataTransfer.getData('text/plain')` | medium | mitigate | Payload is `parseInt`-ed and rejected unless `isPrime` accepts it; rejected drops leave state untouched |
| T-pw2-04 | Denial of Service | unbounded placement growing the SVG and the product | low | mitigate | `MAX_PER_REGION = 8` caps each region, which also keeps every reachable product exactly representable as a plain `Number` |

No package-manager install occurs in this plan (the repo has no package manager), so no package-legitimacy checkpoint applies.
