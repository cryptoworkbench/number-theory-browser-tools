# Phase quick-260929-g19 Plan 01: Venn Diagram - show a live Euclidean Algorithm nested-squares preview on overlap hover Summary

Hovering (or focusing) a linked overlap composite chip in the Venn Diagram tool — the two-circle `A ∩ B` chip, or any of the three-circle `ab`/`ac`/`bc` pairwise chips — now draws a live miniature of the Euclidean Algorithm tool's nested-squares diagram for that exact pair, right next to the chip, without leaving the page.

## What was built

**Ported Euclidean math** (`euclidSteps()`, `computeNestedLayout()`, `NEST_TILE_CAP = 40`): duplicated verbatim from `Euclidean Algorithm/euclidean-algorithm.html` per this repo's deliberate per-file-duplication convention, trimmed to drop the Bezout `s`/`t` recurrence the nested view never reads.

**`showNestedPreview(layer, opts)` / `hideNestedPreview(layer)`**: a small SVG renderer that draws a backing plate, a scaled `nframe` + classed `nsquare`/`ncap` rects, a `gcd(a, b) = g` caption, and a `double-click to open the full view →` hint into a `<g class="nested-preview">` layer, clamped so the panel never clips the 900×520 (two-circle) or 900×700 (three-circle) viewBox.

**`appendCompositeBadge()` gated on `link.previewLayer`**: when present, the chip drops its native `<title>` for `role="img"` + the same text as `aria-label`, gains `tabindex="0"`, and wires `mouseenter`/`focus` to show the preview and `mouseleave`/`blur` to hide it — leaving `data-xref-href` and the existing `dblclick` deep link untouched. Chips without a `previewLayer` (unlinked chips, and three-circle chips before Task 2) are byte-identical to their pre-plan behavior.

**Two `<g>` preview layers** (`#venn-preview`, `#venn3-preview`) as later-siblings inside their respective composite SVGs, cleared at the top of `renderComposite()` / `renderComposite3()` so a chip rebuild (placement, removal, drag, Clear all, or a mode switch) can never leave an orphaned panel.

## Issues Encountered

**Harness fix (test-harness only, no product code touched):** the first `venn-preview-harness.js` draft called `.click()` directly on SVG `<g>` region elements to place primes. `click()` is an `HTMLElement` method; Chrome's `SVGElement` does not implement it, so the very first region-click threw `el.click is not a function`. Fixed by dispatching a real `MouseEvent('click', { bubbles: true })` instead — matches how the harness already fires `mouseenter`/`mouseleave` on chip `<g>` elements. Prime-picker buttons (real `<button>` HTML elements) and `#clear-btn`/`#mode-two`/`#mode-three` continue to use `.click()` directly since those genuinely are `HTMLElement`s.
