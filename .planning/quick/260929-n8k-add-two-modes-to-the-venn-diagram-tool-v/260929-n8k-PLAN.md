<objective>
Add a hover-preview mode switch to the Venn Diagram tool. Mode 2 (default) keeps today's Euclidean nested-squares thumbnail exactly as it is. Mode 1 replaces that thumbnail's contents with a miniature factor tree built by the Factor Tree tool's Balanced (Fermat's Method) logic, ported inline.

Purpose: the singly-overlapping badges already answer "what is this region's number?" with a digit string and "how do you confirm it by division?" with the Euclid miniature. The one question the page cannot answer in place is "what is that number MADE of, split evenly?" — which is the whole point of the Balanced tree. Mode 1 puts that answer under the same hover, in the same panel, without leaving the Venn diagram that produced the number.

Output: one self-contained section added to `Venn Diagram/venn-diagram.html` (Fermat split + balanced tree builder + layout walk + SVG tree renderer), one dispatcher, one extracted panel-geometry helper, one toolbar switch with its own persisted key, and a small block of token-only CSS. No new files, no new dependencies.

**Decision — port the math, do not reach across files.** CLAUDE.md mandates per-file duplication of number-theory helpers and forbids a shared JS module. The Balanced pieces actually needed are small and pure: `isqrt`, `isPerfectSquare`, `fermatSplit`, the balanced branch of `buildTree`, `assignX`, `flatten`. This page already carries an identical, explicitly-commented duplication of the Euclidean tool's `euclidSteps`/`computeNestedLayout` (venn-diagram.html:982-1056) — the new block imitates that precedent, comment idiom included.

**Decision — the switch governs the panel's CONTENTS, not the deep link.** `Factor Tree/factor-tree.html` reads no `?n=` or `?mode=` query parameter (its only URL parameter is `?theme=`, line 5), so there is no factor-tree deep link to point at and inventing one would mean editing a second tool. The badge's double-click therefore still opens the Euclidean Algorithm tool in both modes; only the panel's hint line is reworded in Mode 1 so the panel never promises a full view it cannot open.

**Decision — Mode 1 factors the badge's own number.** In two-circle mode the overlap badge's value and `gcd(A, B)` are the same number, so the choice is invisible. In three-circle mode they differ: the `(A∩B) \ C` badge shows the product of the primes in that lens alone, while `gcd(A, B)` also includes the centre. The tree factors what the badge displays, because that is the number the user is pointing at.
</objective>
