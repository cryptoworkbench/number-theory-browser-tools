## Accomplishments

- The A∩B∩C centre chip in three-circle mode opens the same hover-preview panel the pairwise overlap chips (`ab`, `ac`, `bc`) and the two-circle `A ∩ B` chip already show — same panel geometry (`previewPanelRect()`), same show/hide lifecycle (`mouseenter`/`mouseleave`/`focus`/`blur`), same dispatch on `state.previewMode` (`showRegionPreview()`).

- The centre chip carries no cross-tool deep link and no double-click hint — `appendCompositeBadge()` now tests `hasHref` (link + href present) and `hasPreview` (link + previewLayer present) independently, instead of deriving both from one `link` truthiness check.
- No regression: every previously-linked-and-previewable chip (pairwise ab/ac/bc, two-circle A∩B) keeps its `is-linked` class, hint text, and href byte-identical to the pre-edit baseline; the three exclusive chips (aOnly/bOnly/cOnly) remain untouched (no aria-label, native `<title>`, no preview).

## Decisions Made

- CSS specificity: `.composite-chip.is-previewable` and `.composite-chip.is-linked` are both bare-class selectors (no `rect` child) so they have equal specificity (0,2,0); `is-linked`'s `cursor:pointer` is placed after `is-previewable`'s `cursor:help` in source order, so a chip with both classes (every pre-existing preview+link chip) still shows a pointer cursor, while the centre chip (preview-only) shows a help cursor.
- `isEuclidRange(a, b)` extracted from `euclidHref()`'s inline range check so the centre chip's preview descriptor and the URL-builder can never drift on what counts as "in range" — both call the same named predicate.
- The centre chip's `link` object carries `href: null` and omits `label`; `appendCompositeBadge()` only reads `link.label` inside `hasHref`-gated branches, so no runtime error occurs when `link.href` is `null`.
- Left `showFactorTreePreview()`'s separate over-cap early-return hint ("over 1,000,000 — no balanced tree") unconditional. It is a distinct, pre-existing informational message (not a "double-click to..." affordance), and every centre-chip badge value observed in testing (bounded by `MAX_PER_REGION3 = 3` primes per region across the primes 2–101) stays well under `FT_MAX_N = 1,000,000`, so this branch is unreachable for the centre chip in ordinary use; the threat model's Spoofing mitigation (T-o99-03) targets the double-click hint specifically, which Task 2 gates.
