- `clearStage()` (`:608-611`): sets `equationEl.innerHTML = ''` then `treeArea.innerHTML = ''`. Called at the top of `renderTree()` and on every invalid/too-large input path in `factorize()`.

- `renderTree(n, topFactors)` (`:627-781`): builds and lays out the SVG, then schedules four guarded timers — depth groups at `d*perDelay`, the trunk at `finalDelay + 250`, the star at `finalDelay + 550`, and the result text at `finalDelay + 250` (`:776-780`). Every one of those callbacks opens with `if(localGen !== generation) return;` (four occurrences of that guard in the file). The result callback computes `isPrimeInput = topFactors.length === 1` and calls `popEquation` with `'1'` when `n === 1`, with `n + ' = ' + n + ' × 1'` when prime, and with `n + ' = ' + topFactors.join(' × ')` otherwise.
- `factorize(rawValue)` (`:783-823`): bumps `generation`, validates, and on the empty/non-integer/too-large paths calls `clearStage()` + `setMessage()` and returns **without** calling `renderTree` — so the result element stays empty on those paths. For `n === 1` it calls `renderTree(n, [])`; otherwise it calls `primeFactors(n)`, sets the message, and calls `renderTree(n, factors)`.
- `topFactors` is always `primeFactors(n)` regardless of mode — Balanced mode changes only `buildTree`'s split choice (`:543-558`), never the factor list the result line is built from.
- `readNParam()` (`:859-876`) plus the load handler (`:879-889`): a valid `?n=` lands in Balanced mode on that number, otherwise Classic on 60.
