<harness_recipe>
Write `$SP/venn-thumb-toggle-harness.js` once, in Task 1, and extend it in Task 2. Node standard library only — no install, no dependency. It takes one scenario argument (`t1`, `t2`), serves the checkout root (its own cwd) on an ephemeral loopback port, serves one in-memory `/__driver.html` route, and accepts one POST route on which it records the verdict.

The driver clears `localStorage` AND `document.cookie` for the origin before each scenario (this tool's shared a/b store is cookie-mirrored and cookies are origin-scoped, not iframe-scoped, so a value left by an earlier scenario in the same profile survives into a supposedly fresh frame), seeds only the keys the scenario needs, loads the tool page in a same-origin iframe, waits for that document's load handler to finish, then drives it through its visible DOM only — real button clicks, real dispatched events, never by calling the tool's internals.

Synthesise `mouseenter` / `focus` as plain dispatched events, `wheel` with an explicit non-zero `deltaY` and `cancelable: true`, and `keydown` with an explicit `key`; read `defaultPrevented` off each dispatched event afterwards — that is how "the page still scrolls with thumbnails off" is measured. For the deep-link assertion, replace the iframe window's `open` with a recorder before dispatching `dblclick`. Re-query chip nodes after every toggle: `render()` replaces them, so a node captured before a click is detached and will report stale attributes.

It POSTs `PASS` or `FAIL` with the check count and, on failure, the first mismatch. Spawn Chrome as `google-chrome --headless=new --disable-gpu --no-sandbox --user-data-dir="$(mktemp -d)" --virtual-time-budget=20000 "<loopback driver URL>"`, wait for the POST, kill Chrome, print the verdict, exit 0 only on `PASS`. <!-- planner-discipline-allow: http: --> The loopback URL belongs to the scratchpad harness and is never written into the edited HTML file; the per-task diff gate greps the diff only, so the two cannot collide.

Vacuity-check each scenario before trusting it, as spelled out per task. A gate that passes against a build without the change proves nothing.
</harness_recipe>
