- the engine allow-list, plus one browser-detection mapping (the legacy tag `no` → `nb`);
- two switcher options on all 16 pages;

On top of that template, this task makes the gate tooling data-driven for the languages that follow (ro/hu/lv, then ru/el): one per-language table in i18n-check.js from which the code list and the autonym neutral tokens derive, and a plural guard that covers every supported language instead of a hand-maintained list. - **Q-01 Switcher.**
  - Two lines go directly after the Português (Portugal) option, sv first: value `sv`, lang `sv`, label `Svenska`; then value `nb`, lang `nb`, label `Norsk (bokmål)`.
  - Same 8-space indentation, no `selected` attribute; both lines byte-identical on all 16 pages, so `--header`'s canonical-header identity gate holds.
  - SWITCHER_OPTIONS and every data file use this order: nl, en, de, fr, es, it, pl, pt-BR, pt-PT, sv, nb.
- **Q-02 Code shape and validation.**
  - sv and nb are plain two-letter codes. valid() stays the existing exact, case-sensitive `indexOf`, applied unchanged to `?lang=`, the cookie, localStorage, the storage event and setLang.
  - `no`, `nn`, `SV`, `NB`, `nb-NO` and `sv-SE` are rejected on every channel; a rejected `?lang=` value is not stripped from the URL (existing behavior).
  - persist(), decorateLinks(), applyHtmlLang() and the header comment stay byte-identical (the header already describes a code as two-letter or region-tagged).
- **Q-03 Browser-language detection.**
  - With sv and nb in SUPPORTED_LANGS, the existing unchanged line `var code = String(langs[i]).slice(0, 2).toLowerCase();` and the following `if (valid(code)) return code;` already map every `sv*` tag to sv and every `nb*` tag to nb.
  - Add exactly two lines inside detectDefaultLang's loop, after the Portuguese branch's closing brace and directly before that two-letter line, at 6-space indentation:
    - the comment line `// Norwegian: the legacy macrolanguage tag no (no, no-NO) means Bokmål; nn (Nynorsk) is unsupported and falls through.`
    - the statement `if (parts[0] === 'no') return 'nb';`
  - `parts` is the lowercased tag split on `-` or `_` that the Portuguese branch already computes, so `no`, `NO`, `no-NO` and `no_NO` map to nb. The primary subtag must be exactly `no`, matching the Portuguese branch's exact-`pt` rule, so `nor`/`nob` fall through like any other unsupported tag. `nn`/`nn-NO` are not mapped and fall through to the next preference.
  - ENGINE-SCOPE checks the whole file byte for byte against 23c0cc1 with only these two edits applied, so write both lines exactly as given and touch nothing else in the file.
- **Q-04 Register.** Both use informal **du**, matching nl je / de du / es tú / it tu / pl ty / pt-PT tu.
  - sv imperatives: tryck, välj, klicka, skriv, ange, se, prova, dra, flytta; possessives din/ditt/dina.
  - nb imperatives: trykk, velg, klikk, skriv, angi, se, prøv, dra, flytt; possessives din/ditt/dine.
- **Q-05 Spelling, vocabulary and notation.**
  - sv: standard Swedish; "tal" for number (primtal, sammansatt tal, kvadrattal), delare, kvot, rest, modul, nyckel/nycklar.
  - nb: standard, moderate Bokmål; "tall" for number (primtall, sammensatt tall, kvadrattall), divisor, kvotient, rest, modul, nøkkel/nøkler. Use the masculine-form definite ending on feminine nouns (tabellen, løsningen, siden), and no Nynorsk forms (ikkje, eg, kva, korleis, frå, ein, eit, berre).
  - Compounds are closed in both languages (Faktorträd / Faktortre, nyckelpar / nøkkelpar). Hyphenate only where one element is a symbol, digit, abbreviation or acronym (RSA-nyckel / RSA-nøkkel, φ-funktion / φ-funksjon).
  - GCD/LCM: where a data file already localizes the gcd/lcm notation or the prose noun "the GCD" (rsa.js and shors-algorithm.js, whose other blocks show `mcd(`, `NWD(`, `ggT(`, `mdc(`; euclidean-algorithm.js's prose noun):
    - sv uses `SGD(` / `MGM(` and the noun `SGD`;
    - nb uses `SFD(` / `MFM(` and the noun `SFD`;
    - each choice keeps one casing across its whole block.
  - Where a file keeps `gcd`/`lcm` literal in every language (its header says so, e.g. chinese-remainder-theorem.js), both keep it literal.
- **Q-06 Punctuation and capitalization.**
  - Quotes, if ever needed: ”…” in sv (U+201D on both sides), «…» in nb.
  - No space before `:` `;` `?` `!`.
  - Headings and tool names use sentence case, like fr/es/it/pl/pt.
  - A value containing a straight ASCII apostrophe (the nb genitive `Eratosthenes' sil`) must be double-quoted, like the French nav values in site.js.
- **Q-07 Plurals.** CLDR 48 (node 22.23.1 / ICU 78.2, verified at planning time): sv and nb each have exactly `one, other`, and `one` means exactly the integer 1 (0, 1.5, 2, 5 and 1000000 select `other`). Neither has a `many` category.
  - Every sv/nb plural value is `{ one, other }` in that key order. PLURAL_EXTRA_CATEGORIES stays `{ pl: [...] }`.
  - `one` and `other` may be identical where the noun is invariant: Swedish and Norwegian neuter nouns such as steg, primtal/primtall and sv element have the same indefinite singular and plural, as German already does for rsa.resGiveupBody and sqm.bannerComputed. Where the phrase does inflect (definite forms such as steget/stegen, participles hittat/hittade, -ar/-er plurals such as kvadrater, värden, nycklar, elementer, bitar), both forms must be correct. NEW-PLURAL requires at least 3 of the 11 values per language to differ.
  - `one` carries English one's placeholders, and `other` carries English other's.
- **Q-08 Proper nouns.**
  - Euclid → **Euklides** in sv and **Euklid** in nb (both already NEUTRAL_TOKENS). Eratosthenes, Euler, Fermat, Cayley, Venn, Shor, Bézout, Diffie-Hellman, RSA, DH, ECDH and Sun Tzu are invariant. Alice, Bob and Eve are kept per glossary (d).
  - Genitive: a plain -s with no apostrophe (Eulers, Fermats, Shors, Alices, Bobs). A name ending in -s takes no ending in sv (Euklides algoritm, Eratosthenes såll) and an apostrophe in nb (Eratosthenes' sil).
  - Possessive of a name placeholder (English `{0}'s`, rsa.js only): sv writes `{0}s` (all three names take a plain -s), e.g. `🔑 Generera {0}s nyckelpar`; nb uses the til-construction, e.g. `🔑 Generer nøkkelparet til {0}`.
- **Q-09 Gate generalization (keep tooling generic).**
  - In i18n-check.js, SWITCHER_OPTIONS becomes the one per-language table. LANG_CODES is derived from it, and so are the switcher autonyms in NEUTRAL_TOKENS (new helper autonymTokens). A later language needs one SWITCHER_OPTIONS entry, plus a PLURAL_EXTRA_CATEGORIES entry only if its CLDR categories exceed `one, other`.
  - New helper pluralSelectionGaps(lang): pluralCategoryFindings runs it for every LANG_CODES language. A language whose CLDR rules select a category outside its expected set for any whole count 0..1000 therefore fails `--coverage` until it is listed. Today this adds no finding: fr/es/it/pt's `many` only applies to exact millions.
  - Comments in i18n-check.js state no language count, so later tasks do not have to edit them.
  - `--api` gains two generic loops, so every future code is covered automatically: a detection round-trip for every SUPPORTED_LANGS code, and an upper-cased-code rejection.
  - The `--api` SUPPORTED_LANGS pin stays an independent, hand-written, sorted literal.
  - checkSwitcherPresent's option regex is unchanged, because it already accepts two-letter codes. i18n-browser.js derives from LANG_CODES and needs no edit.
  - The plan's own verify checks derive "existing languages" from the 23c0cc1 engine rather than from hand-written lists. A later planner can reuse them by changing the baseline hash and the per-language tables (DETECT-PARITY classifier, NEW-PLURAL pins, SV-NB-DISTINCT word lists).

- **Q-11 Fix policy and cognates.**
  - Fixes for overflow or untranslated text go into sv/nb wording. Never fix by editing page CSS, markup or script, which breaks en-parity. Never fix by loosening a gate, a word list or a threshold.
  - The four cognate values below are fixed. Each already has a language-agnostic exemption, so only its reason prose is extended to name Swedish (and Norwegian Bokmål where it applies), in both the allowSame entry and the mirrored allowRenderText entry:

  - Keep these distinct from English:

    - `Punkt ({x}, {y})`;
