<objective>
Fix the Venn Diagram preview double-click so it opens the section actually in view on the first try.

Purpose: A previewable composite chip is a `tabindex="0"` SVG group whose `mouseenter` and `focus` listeners both call `showRegionPreview`, which rebuilds the panel and resets `layer._npOffset` to 0. When the user hovers the overlap chip, wheel-scrolls the preview to the Euclidean section and double-clicks, the first mousedown focuses the chip, the focus listener rebuilds the already-open preview at offset 0, and the dblclick handler (which reads `_npOffset` at click time) then picks the Factor Tree target. On a second try the chip is already focused, no focus event fires, and the offset survives. The planner reproduced this in headless Chrome on the current code: offset 206 after the wheel, 0 after a synthetic focus, and dblclick opened `../Factor Tree/factor-tree.html?n=5&lang=en`. The fix makes the show path idempotent per chip: a chip whose own preview is already showing is not rebuilt.

Output: `Venn Diagram/venn-diagram.html` with per-layer preview ownership (`layer._npOwner`) and one shared, guarded show function for `mouseenter` and `focus`; plus a dev-only headless-Chrome regression probe, `.planning/quick/261005-dn2-venn-diagram-double-click-on-a-chip-open/dblclick-probe.js`, that exercises two-circle, three-circle and language-switch paths.
</objective>
