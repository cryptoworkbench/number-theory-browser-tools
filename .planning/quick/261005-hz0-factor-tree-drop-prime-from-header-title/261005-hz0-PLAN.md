<objective>
Two changes to the Factor Tree tool. First, the page header and the browser-tab title stop saying "Prime Factor Tree" and use the tool's plain name in all sixteen languages. Second, every circle that has two circles beneath it gets a narrow, dashed vertical mirror line through its centre. Clicking that circle mirrors the branch below it across the line.

User request, verbatim: "In the tool 'Factor Tree': #1). Don't call it 'Prime Factor Tree' in the header. #2). Make it such that a narrow gray, interrupted, line appears vertically through every circle. When the user clicks the circle while the line is shown, then the two circles underneath got mirrored along the line which the gray line indicates."

How it works today (the planner checked this in the source; the line numbers are from the current file):
- `Factor Tree/factor-tree.html`, line 7 `<title data-i18n="factorTree.title">` and line 268 `<h1 data-i18n="factorTree.heading">`: both hold the English fallback text, with values in `assets/i18n/factor-tree.js` (one `NT.i18n.register('factorTree', ...)` call with sixteen language blocks, the keys `title`/`heading` first in each block, `chipPrime` last). The en-parity check in i18n-check compares markup fallbacks against the en value, so the two must change together.
- `renderTree(n, topFactors)` (lines 403-519) calls the shared `buildFactorTree` → `assignTreeX(root, counter)` → `flattenTree` from `NT.layout` (`assets/nt-layout.js` lines 136-217). It computes `pxX(node)` / `pxY(node)` closures, `radius`, `levelHeight`, and `topPad` = 26. It draws edges into `edgeGroups` (lines 461-472, each `.edge-line` gets inline `strokeDasharray` = `strokeDashoffset` = its length for the draw-in) and circle+text pairs into `depthGroups` (lines 474-484, `circle` class `node-circle <kind>`, then `text`). Depth d is revealed by a `setTimeout` at `d*perDelay`. The equation pops at `finalDelay + 250`, where `finalDelay = maxDepth*perDelay`, and the deepest edges finish their .6s dashoffset transition at about `finalDelay + 600`. Stale timers are dropped with the module-level `generation` counter (`factorize` increments it).
- Every `root`/`internal` node has exactly two children. A composite splits into two factors, and a prime splits into `[1-leaf, prime-leaf]`. `one` and `prime-leaf` nodes have none.
- `assignTreeX`: leaves take consecutive integer slots, and an inner node sits at the midpoint of its first and last child. Classic trees are lopsided. For 60, the root sits at slot 2.25 of a 0-7 leaf span.
- `onLangChange` (lines 599-603) re-renders message, Balanced note and chips only. The tree SVG is never rebuilt on a language change, and there is no resize listener.
- The import block is at lines 304-307; `NT.svg` exports `easeInOutCubic` (unused here so far).

Design decisions (these are the planner's choices; the executor implements them as written):
- MD-1 (request #1): `factorTree.title` and `factorTree.heading` take, in every language, exactly that language's `site.nav.factorTree` value from `assets/i18n/site.js`, so the header, the tab title and the nav link always agree. The values are nl Factorboom, en Factor Tree, de Faktorbaum, fr Arbre de facteurs, es Árbol de factores, it Albero dei fattori, pl Drzewo czynników, pt-BR Árvore de fatores, pt-PT Árvore de fatores, sv Faktorträd, nb Faktortre, ro Arbore de factori, hu Tényezőfa, lv Reizinātāju koks, ru Дерево множителей, el Δέντρο παραγόντων. The markup fallbacks become the en value.
- MD-2 (which circles): the mirror line goes on every circle that has two children, meaning every `root`/`internal` node. That includes a prime node that splits into 1 × p. Leaf circles (`prime-leaf`, `one`) get no line, because nothing sits beneath them to mirror. A line there would advertise a click that does nothing. This is a deliberate narrowing of "every circle": every circle where the mirror can act gets the line.
- MD-3 (when the line shows): the lines fade in on all qualifying circles when the tree has finished growing, at `finalDelay + MIRROR_ARM_AFTER_MS` (700 ms, after the deepest edges' draw-in has ended). The circles become clickable at that same moment, so "the line is shown" and "a click works" are one state, matching the request's "clicks the circle while the line is shown". At arming, the edges' inline dash styles are cleared. The edges are fully drawn by then, so nothing changes visually, but later endpoint moves can no longer cut a line short.
- MD-4 (what "mirrored along the line" does): a click reverses the child order at every node in the clicked circle's branch, which is a true mirror image, left to right at every level. It then re-runs the shared `assignTreeX` over the whole tree and moves everything to the new positions. Relative to the clicked circle, every descendant lands at exactly the mirrored offset across its line (offset d becomes −d), so the two circles directly beneath swap sides. In a lopsided Classic branch, the clicked circle, together with its line and its whole mirrored branch, may also slide sideways so the branch stays in its own lane, and its ancestors re-centre. Circles outside the clicked branch that are not its ancestors never move. A literal reflection with the circle pinned (x' = 2·cx − x) was rejected. For lopsided trees it throws leaves off the canvas or onto neighbouring branches. For 60, pinning the root at slot 2.25 would send leaf 7 to slot −2.5. Clicking again restores. `assets/nt-layout.js` is not modified, so the first, unmirrored render stays identical to today and to the Venn hover miniature.
- MD-5 (animation): a `requestAnimationFrame` tween of `MIRROR_MS` = 450 ms using `NT.svg.easeInOutCubic`. It moves every circle `cx`, label `x`, axis `x1`/`x2` and edge `x1`/`x2` from its current on-screen x to its target. A second click mid-tween restarts from wherever things currently are. A per-view `tweenToken` stops stale frames, and `view !== treeView` stops frames from an old tree. A settle `setTimeout` at `MIRROR_MS + 60` snaps to the targets if the token is still current, because rAF frames pause in background tabs. The planner also measured that under headless Chrome's `--virtual-time-budget` no rAF frame fires until the budget is spent. Under `prefers-reduced-motion: reduce` the targets apply synchronously and the axis fade-in is disabled.
- MD-6 (interaction and accessibility): an armed circle gets class `mirrorable`, `tabindex="0"`, `role="button"` and `aria-pressed`. `aria-pressed` is true when this circle has been clicked an odd number of times. The circle also gets an SVG `<title>` child, created with `svgEl('title')` and filled via `textContent` from `translate('factorTree.mirrorLabel', { n: value })`. The `<title>` is both the hover tooltip and the accessible name. Enter or Space on a focused armed circle mirrors it and calls preventDefault; an auto-repeated key does nothing. The circle shows `cursor:pointer`. A `:focus-visible` ring is drawn as a heavier `var(--text)` stroke (not an outline, which would draw a box), and hover or focus brightens the circle's axis. The axis has `pointer-events:none`, and the existing label `text` already has `pointer-events:none`, so a click anywhere on the circle reaches the circle.
- MD-7 (state lifetime): mirror state lives on the current tree objects and SVG. `onLangChange` never rebuilds the tree, so mirrored branches survive a language change. The callback re-labels each `<title>` through `relabelMirrors()`. A new number, a chip, the Grow button or a mode switch build a fresh tree with nothing mirrored, which is today's `renderTree` path.
- MD-8 (scope): `assets/i18n/hub.js` keeps `hub.card.factorTree.title` ("Prime Factor Tree" on the index card), because the request names the tool's header only. The SUMMARY flags this as a possible follow-up. There are no CLAUDE.md changes, because no module, key contract or convention changes.

New dictionary key `mirrorLabel` (placeholder `{n}`, identical in every language). Wording is consistent with each language's existing "branch" word in the factorTree/hub strings:
