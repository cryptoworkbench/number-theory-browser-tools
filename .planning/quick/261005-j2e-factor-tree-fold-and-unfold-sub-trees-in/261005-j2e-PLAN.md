- FD-3 (animation). Every node view carries a displayed state `{px, py, s, o}`: x, y, scale (0 to 1) and opacity (0 to 1). A hidden node's target is its anchor's centre with s = 0 and o = 0. Its anchor is its topmost folded strict ancestor. Edges follow their endpoints, so an edge into a collapsing child retracts into the parent, and an edge's opacity is its child's o. All phases ease with `easeInOutCubic`.
  - Fold F runs two phases:
    1. `FOLD_MS` = 400. Every descendant of F moves to F's current centre while s and o go to 0. Every other node stays where it is.
    2. `MIRROR_MS` = 450. The model targets: the visible tree re-lays out with F as a leaf, and the hidden nodes ride along at F's moving centre.
  - Unfold F runs the reverse:
    1. `MIRROR_MS`. The model targets, except that every descendant of F is held at F's target centre with s = 0 and o = 0. This opens the space.
    2. `FOLD_MS`. The model targets: the sub-tree grows back out of F.

The visible tree therefore re-spreads across the same width ("reclaims the space"), and with nothing folded it is bit-identical to today.
  - Vertical geometry, the SVG size, the radius and the font sizes stay fixed. This keeps the page from jumping, and the radius can never overlap because folding only reduces the leaf count, which only widens the spacing.
- FD-5 (folded look and inert hidden parts).
  - A folded circle gets class `is-folded` and shows a concentric `circle.fold-ring`. The ring has radius r + 3.5 (`RING_GAP`), stroke `var(--role-input)`, no fill, `pointer-events` none, and is inserted immediately before the node circle.
  - Its mirror axis is hidden and its mirroring is disabled. Disabling means: `mirrorable` class removed, `tabindex` "-1", `aria-disabled` "true", `<title>` text emptied, and an early return in the click/key handlers. Unfolding restores all of these.
  - Hidden descendants get `display: none` once their opacity reaches 0, so they cannot be clicked or focused. Their badges and circles get `tabindex` "-1" as soon as they are hidden in the model, and their handlers return early for any node hidden in the model.
  - If focus is on a control that becomes hidden, focus moves to the folding badge.
- FD-6 (nested state). Fold flags and mirror `pressed` flags of inner nodes are never reset by an ancestor's fold or unfold. `reverseBranch` already reverses children inside folded sub-trees, so mirroring an ancestor reflects the hidden sub-tree too. That is the geometrically consistent result: after unfolding, the sub-tree appears exactly where it would have been had it never been folded.
- FD-7 (root). Folding the root is allowed. The tree collapses to a single circle at `containerWidth/2` (the one-leaf rule) with its ring and a + button. Unfolding restores the tree.
- FD-8 (lifetime). Fold state lives on the current tree objects. `onLangChange` calls `syncControls(treeView)`, which re-labels everything from the model and moves nothing. A new number, a chip, Grow, Randomize or a mode switch goes through `factorize` → `renderTree` → `clearStage`, which gives a fresh tree with nothing folded.
- FD-9 (scope). The equation and message are untouched by folding. There are no changes to `assets/nt-*.js`, `assets/i18n/site.js` or `assets/i18n/hub.js`, and no CLAUDE.md change, since no module, key contract or convention changes. Every colour is `var()`.
- FD-10 (one engine, planner's choice). `moveTree` is generalised into `animateTree(view, phases)`, which `mirrorBranch` and `toggleFold` both use. A phase is `{ ms, targets(view) }`, and `targets` is evaluated when the phase starts, so a chain always aims at the current model.
  - One `view.tweenToken` per action. Each frame and settle timer checks `view === treeView && token === view.tweenToken`, so a new action cancels the old chain and starts from the current on-screen state.
  - Each phase has a `done` flag, set by whichever finishes it first: the frame at p ≥ 1 or a settle `setTimeout` at `ms + 60`. Finishing snaps to the targets, places everything and starts the next phase, and a late frame of a finished phase returns immediately. This replaces hz0's bump-the-token-after-snap fix, which would kill a chain.
  - The start time is taken from the first frame's own timestamp (hz0 fix), with elapsed clamped to at least 0.
  - Under headless `--virtual-time-budget`, rAF frames do not fire until the budget is spent, so the settle timers drive the probe deterministically.
