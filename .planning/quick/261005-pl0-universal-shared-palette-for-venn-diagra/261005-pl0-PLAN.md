<objective>
Make the number palette universal across Factor Tree and Venn Diagram, and let the Sieve of Eratosthenes merge the primes it found into that palette.

- Both tools render one shared, persisted list of numbers from a new NT.store key.
- Venn Diagram gets Factor Tree's Add behaviour, so composites can enter the palette.
- Venn gets a removal path (bin and Delete key) like Factor Tree's.
- An add or delete in either tool shows up in the other.
- Venn chips keep their own neutral styling, not Factor Tree's green.
- The Sieve gets a button that merges its found primes into the palette with no duplicates and reports the result.

Purpose: the user wants one palette, curated once and used in every number tool.

Output: the new NT.store palette API (with migration from Factor Tree's old per-tool key), Factor Tree, Venn Diagram and Sieve wired to it, i18n keys in all sixteen languages, and a regression probe.
</objective>

## Planner decisions (PD) — the executor implements these exactly

- **PD-1 (shared store contract).** Add a new persisted key `number-palette`, exported as `SHARED_PALETTE_KEY`.
  - Payload: a JSON array of integers in ascending order. Duplicates are allowed.
  - Length is at most `SHARED_PALETTE_MAX` = 1000.
  - Each entry n satisfies 2 <= n <= `SHARED_PALETTE_MAX_N` = 1000000000000 (Factor Tree's Classic cap).
  - The validator returns a sorted copy, or null for anything malformed.
  - An empty array is a VALID palette, because a user may have binned everything.
  - `group-params` and `ab-params` are untouched.
- **PD-2 (cookie size).** A cookie value is limited to about 4 KB. A palette of hundreds of numbers would silently fail to set, and the cookie-first read would then return a stale palette.
  - `writeShared` therefore expires the key's cookie (same attributes, max-age=0) whenever the URI-encoded payload is longer than an internal `COOKIE_VALUE_MAX` of 3800 characters. localStorage alone then carries the value.
  - This is harmless for the existing tiny payloads.
  - `readShared` is NOT changed. The phase-7 harness pins its "empty cookie value" behaviour. A real browser deletes a max-age=0 cookie, so the cookie-first regex no longer matches and the read falls back to localStorage.
  - Known limitation, to note in the module header: on Firefox `file://`, a palette too large for a cookie only syncs within one page's own origin.
- **PD-3 (migration, no data loss).** `loadSharedPalette()` reads the shared key and also reads Factor Tree's legacy per-tool key from localStorage, validated by the same rules. Venn never persisted a palette: its 26 primes 2..101 are a subset of the default, so nothing of Venn's needs merging. Cases:
  - Neither is present: write and return the default, the first 30 primes 2..113 (Factor Tree's current default). Keep it as an internal frozen literal, so nt-store.js gains no dependency on nt-core.js.
  - Only the legacy key is present: write and return the legacy list.
  - Both are present: take the max-count multiset merge (each value appears max(countShared, countLegacy) times), sort it ascending, and drop the largest values beyond the cap. Write and return it.
  - Whenever the legacy key was found, remove it from localStorage after the write, so the merge runs once per origin.
  - Otherwise, return the shared list unchanged.
- **PD-4 (read-modify-write).**
  - Every mutation re-reads the store first via `loadSharedPalette()`, applies the change, writes once, and returns the new list. A stale page (bfcache, another tab) therefore never clobbers newer content.
  - Mutations go through `addToSharedPalette(values, unique)` -> `{ list, added, duplicates, overflow }` and `removeFromSharedPalette(value)` -> list.
  - The page then reconciles its DOM to the returned list.
  - A page receiving a `storage` event never writes back, so two open tools cannot ping-pong.
- **PD-5 (duplicates and removal).**
  - Manual Add in either tool keeps Factor Tree's existing "duplicates allowed" behaviour (kaz, user point 2).
  - The Sieve merge and the deep-link "ensure present" path are unique: duplicates are skipped. The user said "doubles do not get added".
  - Removal removes exactly one occurrence of the value.
- **PD-6 (cap — an existing limit, surfaced, not invented).** `SHARED_PALETTE_MAX` = 1000 is Factor Tree's existing palette-read limit, carried over.
  - Add at the cap is refused with a translated "palette is full" message.
  - The Sieve merge adds new primes smallest-first until the palette is full, and reports how many did not fit.
  - A sieve of N = 20000 finds 2262 primes, so the cap is reachable. Surface this in the SUMMARY.
- **PD-7 (Venn Add UI mirrors Factor Tree).**
  - A numeric input (type=number, inputmode numeric, pattern digits, min 2, max 1000000000000, translated placeholder and aria-label) and an Add button.
  - Use the same keydown filter (refuse e, E, +, -, period, comma; Enter adds) and the same `beforeinput` digits-only filter as Factor Tree.
  - Validation order:
    1. empty -> `venn.msg.empty`
    2. non-digits or 0 -> `venn.msg.invalid`
    3. 1 -> `venn.msg.one`
    4. over `SHARED_PALETTE_MAX_N` -> `venn.msg.tooLarge`
    5. otherwise `addToSharedPalette([n], false)`: if `overflow` -> `venn.msg.paletteFull` with {max}, else re-render and `venn.msg.added` with {n}.
  - After an add, the field keeps its value, selected.
  - No Randomize-into-field in Venn. Venn's existing diagram Randomize is unchanged and still draws from its own fixed 26-prime pool.
  - Venn chips keep `.prime-chip` styling for primes and composites alike (no `--role-result` green). Only `width:40px` becomes a `min-width` with horizontal padding, so long numbers fit; the narrow-screen 44px override likewise becomes a min-width.
- **PD-8 (Venn removal).**
  - A bin control (the same SVG and dashed-border style as Factor Tree's `.palette-bin`, colours only via `var()` tokens) sits beside the picker heading. It is an HTML5 drop target, because Venn chips already drag with HTML5 DnD carrying the value as text/plain. It opens (lid and warn colours) on dragover.
  - Delete or Backspace (not auto-repeat) on a focused chip also removes it. Focus moves to the chip now at the same index, else the previous chip, else the Add field.
  - Message `venn.msg.paletteRemoved` with {n}.
  - If the armed value no longer exists in the palette, disarm.
- **PD-9 (Venn composite placement).** Venn regions hold primes only: the stored-region validators require `isPrime`, and simplifyRegions, products and gcd depend on it.
  - Placing a composite c therefore pushes each entry of `primeFactors(c)` as its own token in the target region, inside ONE `commitRegions` gesture.
  - Pre-check: refuse with the existing regionFull warning when region length + factor count exceeds the cap (8 two-circle, 3 three-circle).
  - This applies to arm-then-click, Enter/Space on a region and HTML5 drop, in both modes. The region drop handlers accept any integer >= 2, not only primes.
  - Message `venn.msg.placedComposite` with {n}, {factors} (the factors joined by " × "), {region} and {notes}. Primes keep `venn.msg.placed`.
- **PD-10 (exact-integer guard).** Palette numbers up to 1e12 can now reach Venn, so two clicks could push a circle's number past 2^53 and display garbage.
  - `commitRegions` compares each letter total (via the existing `lettersFor`/`letterTotal`) before and after the gesture.
  - If any letter's total after the gesture exceeds `Number.MAX_SAFE_INTEGER` AND is larger than before, refuse with the warning `venn.msg.tooLargeExact`.
  - Removal and any shrinking gesture are never refused.
  - Placed-token rects use the existing `badgeWidth(text, compact)` for their width, centred on the same slot centre, so a long prime stays inside its rect. Numbers of up to 4 digits look unchanged.
- **PD-11 (Venn heading and hint).**
  - The heading reads "Prime palette" while every chip is prime and "Number palette" once any composite is present, mirroring Factor Tree's `syncPaletteHeading`.
  - `venn.picker.heading` changes value from "Prime picker" to "Prime palette" and a new `venn.picker.headingNumbers` is added. In every language, copy Factor Tree's existing `paletteHeading`/`paletteHeadingNumbers` translations.
  - Rewrite `venn.picker.hint` and `venn.msg.pickFirst` in all 16 languages to talk about numbers and the palette (see Task 2).
- **PD-12 (sync triggers).** Factor Tree and Venn both:
  - On a `storage` event whose key is `SHARED_PALETTE_KEY`: `readSharedPalette(e.newValue)`, and if non-null, reconcile without writing.
  - On `pageshow` with `event.persisted` (back/forward cache): reconcile from `loadSharedPalette()`.
- **PD-13 (Sieve).**
  - A new row directly under the `#banner` holds `<button id="toPaletteBtn" class="ghost" disabled data-i18n="sieve.toPalette">` and `<span id="paletteMsg" class="palette-msg" role="status" aria-live="polite">`.
  - The button is enabled once the current run has applied at least one prime event, and disabled again by generate/reset (via `resetPlaybackState`).
  - On click: `addToSharedPalette(foundPrimes, true)`, then exactly one message:
    - `overflow > 0` -> `sieve.palette.full` with {count: added, max, left: overflow}
    - else `added > 0` -> `sieve.palette.added` with {count, dupes}
    - else `sieve.palette.none`
  - The message state is tracked, re-rendered in `rerenderOnLangChange`, and cleared on generate/reset.
  - The click never pauses, resets or otherwise touches sieve playback state.
- **PD-14 (i18n).**
  - All new or changed keys go in all 16 languages, with English as the source.
  - Plural values are `{one, other}`, except pl/ru `{one, few, many, other}`, ro `{one, few, other}` and lv `{zero, one, other}`.
  - ru/el values use Cyrillic/Greek apart from the `SCRIPT_RULES` allow-list.
  - Text reaches the DOM only via `data-i18n*`, `translate`/`translateInto`, `textContent` or `setAttribute`. Never `innerHTML` with text.
  - Numerals are never locale-formatted.
  - Where the English wording is identical, Venn copies Factor Tree's existing translations (add, addInputLabel, placeholder, msgAdded/msgRemoved, msgEmpty, msgInvalid, the two headings).
- **Scope guard.**
  - `assets/nt-core.js`, `nt-bigint.js`, `nt-svg.js`, `nt-layout.js`, `nt-i18n.js`, `assets/i18n/site.js`, `assets/i18n/hub.js` and `index.html` stay byte-identical to ad0db731508bdf7d8a06f0496b769d6fb2956efb.
  - No new CSS line carries a literal colour.

| T-pl0-01 | Tampering | NT.store validatePalette / readSharedPalette | medium | mitigate | Accept only an array of length <= 1000 whose entries are integers in [2, 1e12]; anything else returns null and the page falls back (PD-1, PD-3). The probe's N4 proves the rejections |
