## Locked decisions (orchestrator; non-negotiable)

- L-CODE: code `id`, switcher label `Bahasa Indonesia`, appended as the 25th option directly after 한국어 (SUPPORTED_LANGS, SWITCHER_OPTIONS, every data file: id is the last language everywhere).
- L-DETECT: browser detection maps id, id-ID, ID_id (any region, any case, - or _) through the existing lowercased two-letter path (no change needed for those). The legacy tag `in` (in, in-ID, IN_id) maps to id in browser detection only, exactly like the legacy Hebrew `iw` -> `he` and Norwegian `no` -> `nb` rules: a new branch testing the first subtag exactly (parts[0] === 'in'), so `in` is never an accepted code on any other channel (setLang, ?lang=, cookie, storage reject it). Collision notes (measured during planning, recorded like the kok/jam precedent T-pbf-02): Ingush `inh` has parts[0] 'inh', so the exact branch does not catch it, and its two-letter prefix `in` is not an allow-list code, so it falls through (no collision); ISO 639-2/3 Indonesian `ind` starts with `in`, not `id`, and is not the legacy tag, so it falls through (browsers send id); Ido `ido` and Idoma `idu` now map to id through the long-standing prefix rule (accepted, effect is only a default UI language the user can change); Malay `ms`, Javanese `jv` and Sundanese `su` are not mapped; `en-ID` stays English.
- L-LTR: left to right; id joins neither RTL_LANGS (engine or checker); no U+2066-U+2069 isolate, U+200E/U+200F mark or U+202A-U+202E embedding in any id value. Switching from he or ar to id removes the dir attribute (existing applyHtmlLang behaviour, asserted).
- L-STANDARD: standard Indonesian (bahasa Indonesia baku): EYD Edisi V spelling (the 2022 successor of PUEBI) and KBBI baku forms, the formal register of Indonesian school mathematics (bilangan prima, faktorisasi prima, FPB/KPK). Never Malaysian/Brunei Malay vocabulary, never pre-1972 spelling, never slang or English code-mixing.
- L-ORTHO: Latin script, plain ASCII letters (standard Indonesian orthography has no diacritics). A non-ASCII letter may appear in an id value only where the English value has it (Bézout, ℕ, Greek variables) or as φ in the totient name; the batch gate's FOREIGN-LETTER enforces this exactly as SQSW-BATCH did.
- L-PLURAL: `new Intl.PluralRules('id').resolvedOptions().pluralCategories` is ['other'] (verified in this repo's Node 22.23.1). Every id plural value is `{ other }` alone; id joins PLURAL_OTHER_ONLY_LANGS in the checker; the engine already renders an {other}-only entry for every count (resolveTemplate falls back to entry.other).
- L-DIGITS: ASCII digits, literal as in English: no dot thousands grouping, no comma decimal (16.8 juta, never 16,8 juta; 1,000, never 1.000). id joins DIGIT_PARITY_LANGS (the languages added after the digit-parity rule), so the parity check catches Indonesia's own separator convention.
- L-FONT: the existing Google Fonts cover plain ASCII; no font link, @font-face, font-family or CSS change.
- L-NOCODE: no page script, CSS, markup or shared-module change except the one switcher line per page and the three nt-i18n.js edits (PAGE-CODE and ENGINE-CODE gates). An overflow or wrap problem is fixed in the id wording, never in CSS.
- L-SOURCE: English is the source of truth; translate every id value from its en entry. Never adapt another language's block (in particular never a Malay-looking or Albanian/Swahili/Dutch phrasing); every key of every namespace gets a value; no key is skipped, shortened or left English.
- L-SPLIT: the volume (943 English keys, 52,213 English characters, 13 plural keys) is translated in batches with their own gates and commits, followed by a term-unification pass and a browser sweep with langs=24 (never more than two headless sweeps machine-wide at once).
- L-DOCS: living docs (CLAUDE.md, .claude/CLAUDE.md, .planning/PROJECT.md, REQUIREMENTS.md, .planning/codebase/*.md) move to twenty-five languages including id, the legacy in -> id detection rule, id in the {other}-only plural list and in the digit-parity list; page/tool/nav counts stay 16.

## Discretion choices (recorded so every batch stays consistent)

- D-SWITCHER: in each page header, directly after the line carrying the 한국어 option, one line with the same indentation: `<option value="id" lang="id">Bahasa Indonesia</option>` (no dir or selected attribute). - D-REGISTER: formal and neutral. Address the reader as "Anda" (always capitalized) only when a pronoun is unavoidable; never kamu, kau or engkau. Instructions are bare imperatives: Klik, Pilih, Masukkan, Ketik, Seret, Tekan, Lihat, Coba, Geser, Gunakan. - D-ORTHO: EYD Edisi V / KBBI baku spellings (silakan, mengubah, praktik, analisis, sistem, kuadrat, objek, tampak, izin, risiko, detail, teknik, sekadar, di mana, mengalikan); the prepositions di and ke are written apart (di layar, ke kanan), the prefixes di- and ke- attached (dihitung, keadaan); the ordinal prefix ke- takes a hyphen before a numeral or placeholder (langkah ke-3, langkah ke-{index}). Capitalization: page titles, headings, nav labels, hub card titles and tab or section labels whose English is in Title Case use Indonesian title case (every word capitalized except dan, di, ke, dari, untuk, yang, atau, dengan, pada, dalam, antara: Pohon Faktor, Kuadratkan dan Kalikan); buttons, field labels, legend entries and sentences use sentence case.
