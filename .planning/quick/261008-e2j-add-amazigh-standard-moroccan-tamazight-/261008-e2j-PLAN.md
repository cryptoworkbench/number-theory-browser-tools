## Locked decisions (orchestrator; non-negotiable)

- L-VARIETY: Standard Moroccan Tamazight (IRCAM standard, ISO 639-3 zgh), the same text in two scripts.
- L-CODE: codes `zgh-Latn` (switcher label `Tamaziɣt`) and `zgh-Tfng` (label `ⵜⴰⵎⴰⵣⵉⵖⵜ`, exactly the output of `zgh-gate.js tf Tamaziɣt`). They are appended after Bahasa Indonesia in that order: SUPPORTED_LANGS, SWITCHER_OPTIONS, and every data file (zgh-Latn then zgh-Tfng are the last two language blocks everywhere). This is a new code shape (a three-letter primary subtag plus a script subtag), matched exactly and case-sensitively on every channel like pt-BR/pt-PT. The engine header comment, the checker header comment and the docs describe it as "the script-tagged `zgh-Latn`/`zgh-Tfng`" next to "the region-tagged `pt-BR`/`pt-PT`".
- L-DETECT: a browser tag whose primary subtag is zgh, tzm or ber (any case, - or _) resolves to zgh-Latn when any later subtag is Latn and to zgh-Tfng otherwise (Tifinagh is zgh's official script). kab, shi and rif are not mapped. Collision notes, measured during planning and to be recorded like the kok/jam/ido precedents (T-e2j-02):
  - The new exact branch runs before the two-letter `slice(0, 2)` fallback, so no Tamazight tag reaches the slice.
  - The slice of zgh, tzm or ber gives zg, tz or be, none of which is a supported code. Belarusian be, Bemba bem and Beja bej fall through to English exactly as before.
  - No supported code can be produced by the slice from a zg/tz/be prefix, so there is no new prefix collision.
  - Side effect (accepted, a default the user can change): Central Atlas tzm and the collective Berber tag ber (also sent by some Algerian stacks, e.g. ber-DZ) now default to Moroccan Standard Tamazight in Tifinagh. Kabyle kab, the Latin-script Algerian variety, is deliberately left unmapped.
- L-LTR: both codes are left to right. They join neither RTL_LANGS (engine or checker). `<html lang>` gets the full code (zgh-Latn or zgh-Tfng), and switching from he or ar removes dir (existing applyHtmlLang behaviour, asserted).
- L-SOURCE: English is the source of truth. Write zgh-Latn from each en value, never from another language's block. zgh-Tfng is never written by hand: `zgh-gate.js derive` produces it from zgh-Latn by the IRCAM one-to-one mapping (D-DERIVE), and the permanent ZGH-TRANSLIT/ZGH-NOTATION findings (Task 1 step C) keep the two scripts equal on every future edit.
- L-NAMES (planner decision, delegated by the orchestrator):
  - Alice, Bob, Eve, acronyms (RSA, AES, DH, DSA, CRT, QFT, OAEP, PNG, SVG, PDF), code identifiers (BigInt, pointAdd, scalarMul, qInv, dP, dQ, kG, aG, bG, aB, bA), the notation words gcd, lcm, mod and log, Blowfish, the unit ms and the key-cap names Enter, Space and Delete stay in Latin letters in both scripts: the keep list, KEEP_LIST in the gate and ZGH_KEEP in the checker. This is the precedent of every non-Latin language keeping Alice/Bob/Eve and the notation Latin.
  - Eponyms are adapted to IRCAM Latin (the D-NAMES table) and then transliterated into Tifinagh like any other word. This matches the zgh Wikipedia, which writes Euclid as ⵓⴽⵍⵉⴷ (Uklid) and Descartes as ⵕⵓⵏⵉ ⴷⵉⴽⴰⵔⵜ, and the ru/he/hi/ar/zh/ja/ko precedent of writing eponyms in the language's own script.
- L-SCRIPT: SCRIPT_RULES['zgh-Tfng'] allows only Tifinagh letters of the IRCAM set for words, plus the keep list and single notation letters. zgh-Latn allows only the IRCAM Latin transcription letters a b c č d ḍ e ɛ f g ǧ ɣ h ḥ i j k l m n q r ṛ s ṣ t ṭ u w x y z ẓ plus the labialization mark ʷ (U+02B7, only after g or k, for gʷ and kʷ): NFC, precomposed ḍ ḥ ṛ ṣ ṭ ẓ, ɛ U+025B and ɣ U+0263. Look-alikes such as Greek ε/γ are rejected. Cross-script guards run both ways:
  - Tifinagh inside zgh-Latn is a ZGH-LETTER finding.
  - IRCAM Latin letters, non-IRCAM Tifinagh letters or a misplaced ⵯ inside zgh-Tfng are SCRIPT-FOREIGN findings.
  - Tifinagh inside a ru/el/he/hi/ar/zh/ja/ko value is SCRIPT-FOREIGN.
  - A letter run mixing Tifinagh with Latin is SCRIPT-MIXED.
- L-PLURAL: both codes use { one, other }, with one meaning exactly 1 and other everything else, with or without Intl. Measured during planning: `new Intl.PluralRules('zgh-Latn')` (and zgh, zgh-Tfng, ber) resolves to the runtime's default locale in Node 22.23.1 and in headless Chrome. Under LANG=fr_FR Chrome selected one for 0 and 1.5; under ru_RU it selected one for 21, few for 2 and many for 0; under ja_JP it selected other for 1. tzm does have CLDR data in ICU (one for 0..1 and 11..99), which is not the rule wanted. The engine therefore fixes the rule itself (FIXED_PLURAL_LANGS) instead of asking Intl.
- L-DIGITS: ASCII digits, literal as in English (comma grouping, dot decimal; the zgh Wikipedia writes 7.8 ⵎⵍⵢⵓⵏ and 8,028 the same way). Both codes join DIGIT_PARITY_LANGS.

## Discretion choices (recorded so every batch stays consistent)

- D-SWITCHER: in each page header, directly after the line carrying the Bahasa Indonesia option, add two lines with the same indentation: `<option value="zgh-Latn" lang="zgh-Latn">Tamaziɣt</option>` and `<option value="zgh-Tfng" lang="zgh-Tfng">ⵜⴰⵎⴰⵣⵉⵖⵜ</option>` (no dir or selected attribute; GATE pagecode rebuilds the Tifinagh label from the table and compares). In each data file the id block's closing brace gains a comma, then `'zgh-Latn': { ... }` follows with the en key set in en key order, quoted like the file's existing blocks (single quotes; dotted keys quoted; the language key itself quoted because of the hyphen, as `'pt-BR'` is). `zgh-gate.js derive` then appends the `'zgh-Tfng': { ... }` block in the same style.
- D-DERIVE: after writing or changing zgh-Latn values in a file, run `zgh-gate.js derive <file>`. derive transliterates every word, copies placeholders, digits, punctuation, keep-list tokens and non-IRCAM notation (p, φ, ℤₙ), and keeps a single IRCAM letter Latin when the English value uses that letter as notation and it sits in a math context or ends a clause. It prints an AMBIGUOUS line where that choice needs review: IRCAM writes clitics and prepositions as separate one-letter words (n "of", d "and/is", s "with", g "in", t, as in ⵓⵔ ⵜ ⵉⴳⵉ on the zgh Wikipedia), and these collide with the variables n, d, s, g, t. Review every AMBIGUOUS line:
  - Correct a wrong choice by changing that one character in the zgh-Tfng value (the Latin letter, or the Tifinagh letter copied from `tf` output), or reword the zgh-Latn value so the variable sits next to its notation.
  - Then rerun `translit`. Its ZGH-NOTATION parity is the authority: every single Latin letter in a zgh-Tfng value must appear as often as that standalone letter in the English value (a/A may appear less often, because English uses them as the article).
  - A rerun of derive keeps every zgh-Tfng value that still aligns with its zgh-Latn value, so hand corrections survive; `--force` regenerates all of them.
  - Never type Tifinagh text from memory.
- D-ORTHO: the IRCAM Latin transcription conventions.
  - No o, p or v: loans adapt o→u, p→b, v→f (Paris is Baris, the way Moroccan Tamazight writes it).
  - The schwa e is written only where IRCAM writes it (aseklu, imḍanen with its two n), and omitted elsewhere (amnzu, tusnakt, tasɣnt, imassn).
  - Words are separated as IRCAM separates them: clitics are separate words with no hyphens (ur t igi; rnu as).
  - Nouns take the annexed state after the prepositions n, s, g, ɣf, sg, d (with), i, ar, zund and after numerals (n umḍan, n tsarut, s usgut, g tbalitt, yan umḍan).
  - In zgh-Latn the first word of a sentence, title, heading, button or label and every proper name start with a capital letter. Tifinagh has no case (derive folds it).
  - Precomposed letters only; ʷ only in gʷ and kʷ.
- D-REGISTER: Tamazight has no T/V distinction. Instructions and buttons use the second person singular imperative, the unmarked form of Tamazight software UIs: Sti (choose/pick), Ara (write/enter), Sit ɣf (click on), Rnu (add), Kkes (remove), Sfeḍ (clear), Ssiḍn (compute), Ssken (show), Ffer (hide), Smrs (use), Sfsx (undo), Ales (redo), Urar (play), Sgunfu (pause), Ssuɣl (reset).
  - Where English has a noun, use a noun (Asurif for Step).
  - Validation messages state the requirement (ixṣṣa ad … ; Ara yan ummid …).
  - Status banners use the perfective or passive (ittwafa … found; ikmml … completed; ittwassiḍn … computed).
  - Address the reader through imperatives and impersonal forms; no kyy/kmm pronoun unless unavoidable.
- D-PUNCT: Latin punctuation, identical in both scripts (the transliteration copies it).
  - Quotes are «…» with no inner spaces, as the zgh Wikipedia writes them. No “ ” ‘ ’ ' or " in any zgh value (QUOTE-STYLE gate); a nested quote is avoided by rewording.
  - No space before : ; ? !.
  - The dash is spaced exactly as in the English value; the ellipsis … as in English.
  - A value whose English has no closing punctuation gets none. Playback glyphs and legend slots ({0} Prime, ▶ Play) keep their space as in English.
- D-GRAMMAR:
  - Head-initial noun phrases with adjective agreement (tasarut tamatayt n Alice, amḍan amnzu amẓẓan).
  - Possession with n, never an apostrophe.
  - Never attach an affix to a placeholder, numeral, keep-list token or name: put a head noun in front (azal n {n}, amḍan {n}, tasarut {0}).
