<objective>
Let the arrow keys switch between subgroups in the Grid view of the Cyclic Groups tool's "Subgroup generated by each element" panel, the same way they already do in its List view (QUICK-HP0-01).

The existing mechanism lives in `Cyclic Groups/cyclic-groups.html` right after `focusCurrentRow()` and the `keyNav` mousemove block (around lines 1726-1762). It is one `subgroupsEl.addEventListener('keydown', ...)` handler. It returns at once unless `state.subLayout === 'list'`, takes only unmodified ArrowUp/ArrowDown, steps `state.gen` one index through `drawn.G.els` (DOM row order is `G.els` order), calls `preventDefault()`, ignores out-of-range targets, sets `keyNav = true` and then calls `selectGen()` + `focusCurrentRow()`. The listener sits on the `#subgroups` list, so it only ever sees keys from a focused row and never takes arrows from inputs, selects or sliders. No hint text or aria attribute mentions the keys, and none will be added.

This plan extends that one handler rather than adding a second one. Vertical keys step by the measured grid column count (still exactly one row in the List view). Left and right step through reading order in the Grid view only, mirrored for right-to-left languages. The guards, the edge behaviour, `keyNav` and the select/focus path all stay the same.

Purpose: the Grid view is the default layout. Right now a keyboard user who clicks a row there can't move between subgroups, while the List view lets them.
Output: the updated handler plus a dev-only probe that proves it end to end in headless Chrome.
</objective>
