Approach (Claude's discretion; the page's state is global, so render cannot be instanced):
- Each extra window's body is an `<iframe>` of this same page in a new embed mode, `ringwin=1`, which shows only the Ring window's contents. This follows the existing `preview=1` precedent (IS_PREVIEW, `:root.is-preview`, previewSrc and previewFrame).
- On file:// the frames are cross-origin to the page (opaque origins), so parent and child talk only through postMessage. The parent recognises a frame by `e.source === frame.contentWindow`. The child recognises the host by `e.source === window.parent`.
- The child reports its full query string. The parent derives the title itself (mode and n give buildGroup's cyclic and label) in the parent's language, and keeps the string as the window's state. That state is used to rebuild the frame after full screen is left and re-entered, to duplicate the window, and to remember it across visits in `cyclic-groups-fs-windows` under a new `extras` list.
- Theme and language: on load the child reads the same storage channels as the page. Live changes arrive as storage events where storage is shared, and always as a `look` message from the parent.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| child frame → page (postMessage) | Any window can post a message to the page; only the page's own extra-window frames may drive a window. |
| page → child frame (postMessage) | The child must accept look messages from its embedding page only. |
| localStorage cyclic-groups-fs-windows → page | The stored desktop state may be old, hand-edited or corrupt. Its q strings end up in iframe src and window titles. |
| child frame → shared stores | An embedded copy must not write group-params or the desktop state, or follow the shared group. Otherwise two rings would ping-pong. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-hz1-01 | Spoofing | the page's message listener | medium | mitigate | Act only when e.source is the contentWindow of one of the page's own frames (fsWins scan). The child acts only when e.source === window.parent. Unknown shapes are ignored. |
| T-hz1-02 | Tampering | readFsState extras | medium | mitigate | Key regex `/^ringwin\d{1,6}$/`, a string q of at most 4000 characters, first entry per key, and q re-serialized by cleanRingQuery. Other fields are validated as today, inside the existing try/catch. The probe's R13 and R14 prove it. |
| T-hz1-03 | Tampering | iframe src and titles built from q | high | mitigate | src is always the page's own location.pathname plus a URLSearchParams string with ringwin=1 forced and preview, theme, lang and noshare removed. Titles come from buildGroup on a validated mode and a clamped n, written with textContent and setAttribute only. The child validates every parameter in loadState. |
| T-hz1-04 | Information disclosure | postMessage target '*' | low | accept | Payloads are group parameters, the theme and the language code, nothing private. On file:// the origin is the opaque 'null', so no narrower target exists. |
