<objective>
On multiplicative and elliptic-curve groups, the main view's formulas lost their formula map to the Complexity / Form preference sliders in 261031-wef. This plan lets the learner open that map anyway, next to the sliders, and watch it move live. The sliders, the generator boxes and a forced base visibly drive the map's knob and its open and closed a/a2 paths. The map stays fully clickable, and the sliders follow it.

The user's request, verbatim: "Make it such for EC and multiplicative groups that I can open the map anyway, and then see how the complexity + form slider + generator boxes determined the moving around in this map"

Purpose: the sliders are the easy control, while the map shows the whole grid of formula forms. Seeing both at once teaches how the two slider dimensions and the base choice map onto that grid.

- Two English-only strings in `assets/i18n/cyclic-groups.js`.

  - The toggle opens or closes the map for every slider pair at once, through the single setting `state.fmapOpen`.

## Planner judgement calls (record them in the SUMMARY as J-01..J-08)
- **J-01 SLS is not drawn (D-03).**
  - `formulaMap` already draws SLS faded and disabled whenever `reach.sls` is false. That happens only on non-additive groups, because `mapReach` sets `sls: G.mode === 'additive'`. (The orchestrator's note says the map was once shown "without SLS"; m2b and pm3 show it was drawn faded and disabled instead.)
  - When `!reach.sls`, `formulaMap` skips the two SLS nodes, their two stops and the `sls` dotted path. The wrapper takes class `no-sls`, and the drawing crops to 172 x 58: viewBox `0 0 172 58`, with `.fmap.no-sls` and its `.fmap-svg` at height 58px. The lowest kept node, LCM at y 47 with h 16, ends at 55; the knob grows 1.5px.
  - ℤ/nℤ always has `reach.sls` true, so its map is byte-for-byte the same, apart from the `data-id` hooks in J-05.
- **J-02 Placement.**
  - **Desktop:** the map is a third grid column: pair | map | formula. Each formula row keeps its height, because the cropped map (172 x 58) is no taller than the pair (186 x about 70). The base row still spans every column.
  - **Single column** (phone, `max-width:720px` viewports, which covers a narrow `?ringwin=1` iframe, and a desktop ring head too narrow): pair, map and formula stack, each centred.
  - **The narrow-head guard** lives in `fitSubFormulaBox`:
    - A desktop box with `fmap-open` takes `is-stacked` (single column) when `subFormulaRoom(box)` minus the pair's width, the map's width and two column gaps is below `FMAP_STACK_MIN = 220`.
    - The guard is re-evaluated on every fit, and `fitRingHead` runs it on resize.
- **J-03 The toggle.**
  - `button.fsl-maptoggle` is the pair's last child. It is absolutely positioned at the pair's top-right corner, on the line of the Complexity caption, so the pair keeps its footprint.
  - It must not overlap a notch. Size: 18 x 14 on a desktop and 22 x 18 on `:root.is-mobile`; on a phone the pair takes enough top padding for it.
  - Its look joins the `.lb-lock` / `.lb-scroll` button rules (~1699-1704): a `--panel-border` outline, dim text, and the accent pressed state for `aria-pressed="true"`.
  - Icon: a small inline SVG (stroke `currentColor`, no fill), viewBox about 14 x 10. It shows only the seven non-SLS nodes as small rounded rects in their map arrangement: three columns (JN, short, full) and three rows (GCD, a2/a, LCM), with JN level with the LCM row as on the map. Nothing else: no edges and no knob. (Build icons exactly as described.)
  - `title` and `aria-label` are both `translate(fmapOpen ? 'cyclicGroups.fslMapHide' : 'cyclicGroups.fslMapShow')`, the same pattern as `logLockButton`.
- **J-04 Sharing scope.**
  - `state.fmapOpen` is one view setting, with no `R` twin.
  - The holder sends it to the isomorphism pane in the shared payload (`isoSharedAll` gains `fmapOpen`; `applyIsoShared` takes it with `flag()`). The pane's toggle relays it with `tellHost({ isopane: 'fmapopen', value })`.
  - `swapPaneGroup` keeps it across the swap: add it to `keep`, because `loadState(paneQ)` would reset it from the pane's query.
  - An independent `?ringwin=1` window keeps its own value. Its own query carries it, and it reports changes through `mirrorToUrl`'s `ringwin:'state'` post. This is how `logbaselock` behaves.
  - `isoHref` drops it for a new tab, also as it does `logbaselock`.
- **J-05 Liveness by a carry across the rebuild (D-04).**
  - The formula box, with both controls, is rebuilt on every render. So `.fmap-knob`'s declared `.2s` transition has never run (m2b SUMMARY, "Not done / limits"), and the slider knobs jump the same way.
  - Snapshot: when `hasSliders(G)` and the box was built for the same `G.key` (a module variable `fmapCarryKey` set at each build), `syncSubFormula` first records from the old box:
    - each map's `data-at`;
    - the `is-closed` state of its dotted edges and its a/a2 nodes, by `data-id`;
    - each slider's `--v` and its knob's inline `left` (set while dragged).
  - Carry: after the new box is inserted and fitted, `fmapCarry` puts each changed knob, edge or node at its old state, forces one reflow (`void el.offsetWidth`), then sets the new state, so the transitions run.
    - The map knob uses the existing left/top/width/height transition.
    - New `transition: stroke .3s` on `.fmap-edge` and `opacity .3s` on `.fmap-node` give the fade.
    - The slider knob uses its existing `left` transition, driven by `--v`.
    - All of it is off under `prefers-reduced-motion`.
  - Scope:
    - It applies only on slider groups, so ℤ/nℤ's map stays as it was.
    - It covers every way state changes: slider, map click, box pick, wheel, right-click switch, forced set, settle snap-back.
    - A map just opened, or a new group, has nothing to carry.
  - To find knobs, edges and nodes without a layout read, the module-level helper `fmapPut(el, id, grow)` replaces the `put` closure inside `formulaMap`, with the same code. `formulaMap` also adds `data-id` to each `.fmap-node` `g` and to each dotted `.fmap-edge.is-cond` path (abs / pos).
- **J-06 Force pulses on the map (D-04).**
  - Today only the box and, on slider groups, the neither notch pulse during a force.
  - `forceMapPosition` records the node in `logForce` (`id: id`) in both of its branches. On a slider group it paints `.fmap[data-f=f] .fmap-stop[data-id=id]` next to the notch.
  - `formulaMap` runs the same stale check as `formulaSliders` (`logForce && !logForceLive()` → `stopLogForce()`). On a slider group it re-paints that stop while `logForce.f === f && logForce.id === id`.
  - `stopLogForce` also clears `.fmap-stop.is-force-pulse` and `.fmap-stop.is-force-set`.
  - New keyframes `fmap-force-pulse` (.55s x 2) and `fmap-force-set` (1.1s) keep the timing of `lb-force-pulse` and `lb-flash-ok`. Each draws a `var(--role-result)` ring (box-shadow) and a translucent `color-mix(in srgb, var(--role-result) 30%, transparent)` fill. Translucent, because the label lies over the node, and an opaque fill like `lb-force-pulse`'s would hide the node's text.
  - Snap-backs:
    - A hint click on a closed a/a2 or neither changes no state on either control: both stay put, and the boxes flash.
    - A settleMaps snap-back (h moved) slides both knobs through J-05.
- **J-07 The map has no drag.**
  - Its existing input is a click on a stop (radio `change`), the native radio arrow keys, and a `dblclick` on a closed a/a2 stop.
  - "Dragging its knob" maps to these, untouched. No drag is added.
- **J-08 Band highlight (D-06, nice to have).**
  - The sliders' single commit path `go()` records `fslBand = { f, kind, v, t0: Date.now() }` just before `setFormulaToken`.
  - `formulaMap` on a slider group, while `fslBand.f === f` and less than 900 ms have passed, draws one `rect.fmap-band` first in the SVG, behind every edge and node:
    - complexity: the column band at x = [12, 62, 152][v], 36 wide, full height;
    - form: the row band at y = [47, 28, 9][v] (LCM, neither, GCD), 18 high, full width.
  - It has a one-shot fade-in/out animation (`fmap-band`, about .9s, delayed by `Date.now() - t0` so a rebuild continues it) with fill `color-mix(in srgb, var(--accent) 16%, transparent)`. It is not drawn under reduced motion.
  - If it reads as intrusive in the screenshots, drop it and say so in the SUMMARY.
