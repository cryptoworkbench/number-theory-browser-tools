# Phase quick-261106-m53 Plan 01: Cyclic Groups subgroup-to-group merged panel Summary

A subgroup locked to a group (for example Z/12Z with <2> locked to Z/6Z) now shows one merged bottom panel: every row of G on the left, a right side `{phi(members)} = <phi(g)>` only on the rows whose generator lies in the locked subgroup, and the lock never breaks when another row is selected.

## What was done

Commit `2288f26` (single `feat(cyclic-groups)` commit on main, touching only `Cyclic Groups/cyclic-groups.html`, +89/-45). The plan asks for one commit at the end rather than one per task, so tasks 1 to 3 landed together after each task's probe check had passed.

Task 1 (tracer):
- New field `isoPane.sub` (the locked subgroup's generator). `openIsoPane(a, g, sub)` takes it; `openOwnPane` and the `hostBlank` literal write `sub: null`.
- `isoLinkGen()` returns the pinned subgroup after the whole-group `isoPane.g` branch and before `state.gen`. `isoLinksWholeGroups()` returns false while a subgroup is pinned (so selecting the `<01>` row cannot turn the link "whole").
- `subInterlocked()` holder branch is now `isoOrder() > 0`, so a subgroup link merges the same way a whole link does. `syncInterlock()` pins `isoPane.sub = isoLinkGen()` when the merge turns on for a non-whole link (whole links keep the `isoPane.g` pin). The existing select message already sends `k = -1` for rows outside S, so the pane shows no subgroup.
- `syncIsoLink()` drops the pin once the pinned subgroup is no longer isomorphic to the pane's group.
- `renderMergedSubgroups`: `inS(x) = phi(x) !== undefined`; rows outside S get no `.sub-row-r`, no right tooltip, and a left-only aria-label; `subExports[1]` lists only S rows with `null` lines for the others; `isoLinkGen()` and `isoOrder()` joined the render signature. New helper `isoSortImage`.

Task 2 (expand):
- `mergedSortRight()` replaces the four `subInterlocked() && state.subSortR` conjunctions (plus `sortG` in the render and the sort select's value). The "Natural order on the right" option is offered for whole links only.
- `subGcdDivider`: `d = K.order / order`; the right half is built only when `H.order % order === 0`.
- `exportRows` keeps only rows with a defined image; the context menu offers "Export subgroup" on the right half only when its line is a string.
- `syncSubExpr` fills the pane's expression row for a non-cyclic holder via `syncMergedExpr`.
- `swapPaneGroup` reopens on the pinned subgroup; `swapHostGroup` maps the pin through the image.

Task 3: i18n gates, commit, SUMMARY.

## Discretionary decisions as implemented

- DISC-1: the pin survives an unlock while the pinned subgroup stays isomorphic to the pane's group; the open padlock relocks on the same `<2>`, even with `<03>` selected (probe `unlock`). It is dropped in `syncIsoLink` otherwise.
- DISC-2: sort option `r` is not offered for a subgroup link; a stored `state.subSortR` is ignored there (`mergedSortRight()`), not erased.
- DISC-3: `isoSortImage(G, phi, g)` writes `phi(g)` when defined, else `phi(g^(|G|/|S|))`. Used in the pane's "Generator follows the sort", the sort options' "Exponent of g and h" and the gcd divider's right line. For Z/12Z with `<2>` locked to Z/6Z it reads "Exponent of 1 and 1" and so on, never undefined.
- DISC-4: a gcd divider has its right half only when its rows lie in S (`H.order % order === 0`); d is `|H| / order` there. In the probe the dividers of order 12, 6, 4, 3, 2, 1 have right halves on 6, 3, 2, 1 only.
- DISC-5: a non-cyclic holder ((Z/8Z)* with `<3>` locked to Z/2Z) merges; the pane's expression row is filled; right sides on rows 1 and 3 only.
- DISC-6: the pane-side export lists only S's rows (6 lines for Z/6Z); its `lines` stay index-aligned with the left list with `null` outside S.
